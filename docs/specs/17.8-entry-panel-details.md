# Spec 17.8 — Entry panel details: centered, labeled steppers; a readable label and rest; duration and distance steppers; the edit sheet (web)

**Status:** v0.1 (2026-11-08). **Phase A built** (2026-11-10, branch `feat/spec-17-8a-live-panel`); Phase B not started.

**Source:** the whole-app Impeccable critique of 2026-11-08 (23/40), step 4 of its agreed fix order (the details around Spec 17.7's controls). The owner lifts in pounds on an iPhone, likes the large numbers and buttons, and wants them kept.

**Kind:** UI (web only). **No API, `@sin/core`, migration, CSP or env change.** Two phases, each its own PR: **A** the live panel (steppers, label, rest); **B** the fields that have no stepper yet, the edit sheet, the set rows. One item is split off as a deferred API follow-up (§12, F1).

**Depends on:** Spec 17.4 shipping first (next-set carry, the 56 px Log button, the reserved status line, the scroll to the panel) and Spec 17.7 (Segmented in the sheet, the Warm-up and More row, the panel label's type suffix following the draft). Spec 17.1 (steppers, rest, D10), 17.0 (tokens), 18.0 (the edit screen shares `SetFields`), 18.1 (calories, carries).

**Design refs:** `apps/web/PRODUCT.md`, `apps/web/DESIGN.md` (numbers are the content; "icons always beside a text label"), `apps/web/CLAUDE.md` (Workout screen "now", Planned sets, New exercise types UI).

## 1. Purpose, scope & non-goals

**Purpose.** The panel's numbers are large, but the controls around them are small or misplaced. Verified against the 01 capture's layout file (390 × 844) and the code:

- The ± buttons are 48 px tall beside 60 px number inputs, and `align-items: end` (`NumberStepper.module.css:8`) aligns them to the bottom of a column that also holds the label and the unit line. At 390 px the weight input's center is at y 927 and its buttons' at y 954, 27 px lower.
- The buttons are an icon with only an `aria-label`: no visible step size, and they break "icons always beside a text label".
- "Set 2 of 4" and "Rest 1:42" are `--font-size-sm` (14 px) and the exercise's name is in the card's heading, which scrolls out of view.
- Duration (Minutes, Seconds) and distance have fields and no steppers. A Plank planned as "45–60 s" opens empty with Log disabled (capture 24).
- Those fields are left-aligned beside centered steppers.
- The Log button says "1000 m", the row after it "1,000 m".
- The edit sheet's text fields do not select their text on focus, and the sheet has none of the large numbers.
- A logged row looks like plain text, not a button.

**In scope**
1. Centered, larger, labeled steppers with accessible names that name the exercise.
2. The panel label: exercise name, set, a per-set target, rest at figure size, a visible "Ready".
3. Duration and distance steppers; centered figure fields.
4. One number format on the Log button and the row.
5. The edit sheet: steppers, select-on-focus.
6. A muted cue on logged rows.

**Non-goals**
- Seeding duration or distance from the plan (needs API work; F1).
- Sound, vibration or notification on rest ending (17.1 D10, closed by the owner).
- The Segmented, Select, Warm-up, More, Options moves (Spec 17.7).
- Undo, and the confirm on Delete set (17.5). This spec leaves the sheet's action row alone.
- Moving Change Time (checked, §12 O3).
- The docked panel (17.9, a draft). If built it supersedes parts of this spec (§12).
- A per-weight-unit smaller step, long-press repeat, plate math.

## 2. Acceptance criteria

### Phase A — the live panel

1. **Centered.** In the entry panel, each stepper's ± buttons have their vertical centers within 1 px of the input's center, for weight, reps and calories, at 390 × 844 and 320 × 568 (a harness measurement). Label above, unit text below the row, as today; the row is a grid with `align-items: center`.
2. **Larger buttons.** The step buttons use a new token `--stepper-size` (3.5rem, 56 px), in both axes, up from 48 px. The stepper row's height stays the input's 60 px, so the panel is no taller. The "fits two at 320 px" token `--stepper-min-width` is raised to match (14rem). At 320 × 568 a weight of "102.5" shows in full, not clipped (harness).
3. **Visible steps.** Each button's text is its step: "−5" and "+5" for lb, "−2.5" and "+2.5" for kg, "−1" and "+1" for reps, "−5" and "+5" for calories, using the true minus sign (U+2212), in `--font-size-lg`. The button holds no icon (the icons-beside-a-label rule). `NumberStepper` takes the visible text as a prop. `MinusIcon` and `PlusIcon` stay exported and unused by it.
4. **Names.** A step button's accessible name starts with its visible text and names the exercise (WCAG 2.5.3, and 17.1 AC38): "−5 lb, decrease weight for Overhead Press", "+1, increase reps for Overhead Press", "−5, decrease calories for Echo Bike". The unit is the draft's, so the name follows a unit change. The Log-result sheet's rounds and reps steppers (`ResultSheet`) use the same component and take the same change: visible "−1" / "+1", names "−1, decrease rounds", keeping their copy in `resultCopy.ts`.
5. **The panel label.** The panel's label row leads with the exercise's name (`--font-size-md`, bold, `--color-signal`, the panel's existing label color pair), and a second line with the set ("Set 2 of 4", with 17.7's draft-type suffix) and, when the plan has one, `target {reps}` ("Set 2 of 4 · target 6–8"). Both lines are at least `--font-size-md`. The target line uses `--color-text`, so no new color pair is needed. The exercise's name is not repeated for a screen reader: the form keeps its `aria-label`.
6. **Per-set target.** Built from the next planned row (`nextPlanned`), by a pure `setTarget(row, modality)` beside `setLabel` (*amended in Phase A:* it reads only the measures the exercise's type can show, so a stale row, a Plank still holding 8 × 60 kg, advertises no target): reps as `6–8` or `5`; with a planned weight, `6–8 @ 30 kg` (`formatWeight` and the row's unit); a row with only a weight reads `30 kg`; no target for an extra set, no plan, or a row with neither. It is positional, like the label (10.2 AC20).
7. **Rest at figure size.** `RestReadout` renders the countdown in `--font-size-figure` / `--font-weight-figure` / `--font-stretch-figure`, at the label row's right, wrapping below the label when it does not fit (320 px). "Rest" is a smaller caption inside the same `role="timer"` element, so the element's text is still "Rest 1:42" (the existing rest tests keep their text queries) and it is still no live region (17.1 AC48).
8. **Ready is visible.** At zero the readout shows "Ready" at the same figure size with a filled ground (`--color-signal`, `--color-on-signal`) until the next log. It is a state change, not an animation. (owner, 2026-11-08, accepted recommendation; §12 O1.) `RestReadout.module.css` joins the `roles.test.ts` `SIGNAL_ALLOWED` list with that reason.
9. **Still silent.** No sound, vibration or notification is added (17.1 D10); the existing scan (`rest.hygiene.test.ts`) passes unchanged. *Phase A note: its silence scan is unchanged; its "the readout uses no teal" check (17.1 AC54) now excepts the `.ready` block (AC8).*
10. **No layout shift.** The label row is always the same height whether a rest is running or not, so a rest starting or ending does not move the steppers (a harness measurement at 390 px).

### Phase B — fields and rows

11. **Duration steppers.** For a modality with a duration, the entry panel shows `[−5 s] [minutes : seconds] [+5 s]`. A tap steps the total seconds by 5, clamped to 0 … `SET_DURATION_S_MAX`, and writes the minutes and seconds fields through the ordinary `onChange` (so it is an edit, 17.1 AC21). Blank fields step from 0. Seconds never exceed 59 after a step (0:59 + 5 s = 1:04). A button at its limit is disabled. Names: "−5 s, decrease time for Plank", "+5 s, increase time for Plank".
12. **Distance steppers.** For a distance, the field gets steppers whose step depends on the draft's distance unit: 10 for m and ft, 0.1 for km and mi. Values step in integer milli-units (as weight does), so 0.1 + 0.2 is exactly 0.3. Up is disabled when the next value would exceed `SET_DISTANCE_MAX` in meters (`toCanonicalMeters`). Visible text "−10" / "+10" or "−0.1" / "+0.1"; names "−10 m, decrease distance for Farmer Carry". The carry's label keeps naming its unit ("Distance (ft)").
13. **Centered figures.** The entry panel's duration and distance fields are `text-align: center`, as the stepper figures are.
14. **No seed from the plan.** A plan holds no duration or distance (Spec 09.1 D8), so the first set of a duration exercise still opens empty and Log stays unavailable until a value is entered. After one set, copy-forward fills the next (unchanged). No new request. See F1.
15. **One number format.** The Log button's text uses the same grouping as a logged row: a distance of 1000 reads "Log 1,000 m" on the button and "1,000 m" on the row, and the same for a weight of 1000 or more. The draft's input text stays ungrouped (it is parsed). `logLabel` uses `formatCount` for weight and distance; `formatWeight` stays for field text and target lines.
16. **The edit sheet has steppers.** In the sheet layout (`SetEditSheet` on the live screen and `EditSetForm` on the edit screen, which share `SetFields`), weight, reps, calories, duration and distance use the same steppers, centered and labeled, with the same names (AC4). Unit and set type use 17.7's Segmented. The sheet's Save, Delete set and error behavior are unchanged.
17. **Select on focus.** Every text input in `SetFields`, in both layouts, selects its content on focus, as the stepper's field does (17.1 AC20), so typing replaces. Verified by a `select` spy; the behavior on iPhone is not asserted here and is a phone-check item.
18. **Rows look tappable.** A logged set row on the card (live and edit screens) ends with a `PencilIcon` in `--color-muted`, `aria-hidden`, beside its text. The row stays one button with the same accessible name and 44 px height; the "Needs data", "Not saved yet" and "Couldn't save" tags keep their place before the icon.

### Must keep, docs and verification

19. **Regression guards.** `seedDraft` is the one builder of a draft and is untouched (17.1 AC21; the `now.hygiene.test.ts` scan that `SetFields.tsx` and `NumberStepper.tsx` never call `dispatch(` or `seedDraft(` passes). Draft persistence, the 600 ms double-tap window, focus on the bar's button, one primary `Button`, offline queueing and 17.4's and 17.7's behavior are unchanged. Existing tests change only where this spec amends a criterion.
20. **44 px targets and no overflow.** Every new control is at least `--tap-target-min` in both axes, and the panel and sheet have no horizontal overflow at 320 px (harness, extending 17.1 AC24's check).
21. **Docs consistent.** The cross-doc updates in §12 are made.
22. **Every behavioral AC has a tagged test.** AC3–AC9 and AC11–AC19 have at least one test named `17.8 ACn — …`, enforced by an `acTags.17-8.test.ts` scan. AC1, AC2, AC10 and AC20 are harness measurements (§10).
23. **Visual review.** The screenshot harness captures the panel in weight × reps, duration, carry and calories forms, with a rest running and at "Ready", and the edit sheet, light and dark, 390 and 1280 px and 320 × 568.
24. **Phone check (owner).** On the iPhone, in pounds: the buttons feel centered and readable; "−5 / +5" is clear; the label and rest are readable at arm's length; a Plank can be logged with the steppers; "Ready" is noticed when the rest ends; tapping an edit field selects its number.

## 6. Behavior & logic

### 6.1 Steppers

`stepper.ts` grows `stepDuration(minutes, seconds, direction)` returning `{ minutes, seconds }`, `durationAtLimit`, `DISTANCE_STEP` (m 10, ft 10, km 0.1, mi 0.1), `stepDistance(text, unit, direction)` and `distanceAtLimit(text, unit, direction)`. All are pure and use the integer milli-unit approach of `stepWeight`. `NumberStepper` gets `decreaseText` and `increaseText` props and a layout in which the label sits above the row and the buttons share the input's row (the `Field` control function returns the row, so the label and any error stay `Field`'s; the unit text sits under the row). A duration stepper is the same component with two fields in its center slot, so it is a sibling variant, not a second implementation.

### 6.2 The label

`EntryRow`'s label block renders the exercise's name, then `setLabel(...)` (17.7's draft-aware version), then `setTarget(row, modality)` when planned (the modality keeps a stale row's measures out, AC6). `RestReadout` stays in the same block.

### 6.3 Number format

`logLabel` calls `formatCount` for weight and distance. The Spec 17.1 §6.6 table is amended: "Log 1,000 m · 25:00". Weight with a unit that differs from the profile still appends the unit.

### 6.4 The harness fixture

`scripts/screens/data.mjs` builds a plan's `targetSets` from working rows only (`working.length`), while production derives it from every row, warm-ups included (`deriveTargets`). The fixture is changed to match production so the card line and "Set 2 of 4" agree in captures (§12, rejected finding R1).

## 12. Decisions & open questions

- ✅ **D1 — Step buttons show their step as text, not an icon.** The lifter should know what one tap does without remembering the unit rule (5 lb, 2.5 kg). Text also satisfies the icons-beside-a-label rule, which the icon-only buttons broke. The accessible name starts with the visible text and adds the exercise, so voice control ("tap minus five") and screen readers agree.
- ✅ **D2 — The row is centered by structure, not by margins.** Putting the buttons in the same grid row as the input keeps them centered when an error or a unit line changes the column's height; a computed `margin-top` would drift.
- ✅ **D3 — 56 px buttons, not 60.** At 320 px the panel is 224 px wide inside its padding; 2 × 56 + 16 leaves 96 px for "102.5", which is the figure's minimum (the same arithmetic behind `--stepper-min-width`). 60 px buttons would clip it. 56 px also matches 17.4's Log button.
- ✅ **D4 — Rest is silent.** Spec 17.1 D10, the owner's ruling, is kept. The answer to "nothing draws the eye when rest ends" is a visual state, below.
- ✅ **D5 — A duration steps the total seconds.** The draft keeps two fields (a phone's numeric keypad has no colon, Spec 06.1 D10); a step rewrites both, so 0:59 + 5 s reads 1:04.
- ✅ **D6 — The Log label and the row share one format.** The label mirrors `formatSet` (17.1 §6.6); a different grouping on the button was a bug.
- ✅ **D7 — Change Time is not moved.** Spec 18.0 D8 and D22 (the owner's decision, from mockups) put it on the live header's second row on purpose, as the first tap of the forgotten-workout flow. See O3.
- ✅ **D8 — The panel's first line is the exercise name.** (owner, 2026-11-08, accepted recommendation). The card heading scrolls out of view when the panel is on screen, so the name must travel with the panel; a screen reader keeps the form's `aria-label`.
- **Roles allow-list reason (AC8).** `RestReadout.module.css` joins `SIGNAL_ALLOWED`: "Ready" is the "do this next" state of the current-set panel, the same role as `EntryRow.module.css` (17.1 D12).

**Settled (owner, 2026-11-08, accepted recommendation): each recommendation below was taken.**

1. ✅ **How should "Ready" look?** *Recommendation: a filled teal pill at figure size, text "Ready" (never color alone), static.* It is the loudest thing the design allows without sound or vibration. Alternatives: only larger and bolder (cheaper, quieter); or also tint the whole panel's ground at zero (loud, but it fights the "tint, not outline" panel rule). AC8 assumes the pill.
2. ✅ **Duration and distance step sizes.** *Recommendation: 5 s; 10 for m and ft, 0.1 for km and mi* (the design review suggested 5 s and 10 m; the decimal steps are added here). A first hold of 45 s from empty is nine taps, so typing stays the faster route until planned durations exist (F1); a 15 s step would shorten it but make 5 s precision slower.
3. ✅ **Change Time's weight.** It is a 44 px secondary button on the second header row, the same weight as Workout menu above it. It is only on screen before the lifter scrolls to the panel, so it does not compete with logging. *Recommendation: leave it as D22 decided.* A quieter style would need a new button variant or a text link; 18.0's AC34 says "secondary".
4. ✅ **Should the edit screen's sheet also get steppers?** It shares `SetFields`, so AC16 gives it to both. *Recommendation: yes*, for one consistent form; the pessimistic save is unaffected.

**Findings from the design review, checked against the code**
- **Confirmed:** the 27 px center offset; 48 px buttons beside 60 px inputs; 14 px rest and set label; the empty first duration set; left-aligned figure fields (`.figureInput` has no `text-align`); "1000 m" on the button (`logLabel` uses `String(distance)`) against "1,000 m" on the row (`formatCount`); no select-on-focus in the sheet's text fields; plain-looking logged rows.
- **R1 — Rejected: "'3 × 6–8 @ 30–47.5 kg' above 'Set 2 of 4' because warm-ups count in one and not the other."** In production the card line's count is `deriveTargets(rows).targetSets`, which is every row, warm-ups included, so it would read "4 ×". The mismatch is in the screenshot harness's fixture, which counts working rows only (`data.mjs`). The per-set target is still worth showing (the card's line mixes warm-up and working reps and weights into one range), so AC5–AC6 stand, and §6.4 fixes the fixture. Not specced as a production bug.
- **R2 — Narrowed: "Duration and distance may not be seeded."** Confirmed: a plan never carries either (Spec 09.1 D8, FI-11), and the Plank's "45–60 s holds" is the item's free-text note (`notes` in the fixture), not a field. So seeding needs API and plan-model work and is split off (F1). The steppers do not need it.
- **Not a bug, pre-existing:** the ± buttons break the icons-beside-a-label rule (icon plus `aria-label` only). AC3 fixes it.
- **Change Time:** present at equal weight, as claimed; settled by 18.0 D8 and D22, so not changed (O3).

**Deferred follow-ups (none is in this spec; another session is working in `apps/api`)**
- **F1 — Planned duration and distance (FI-11).** An additive migration (`duration_s`, `distance`, `distance_unit` on the plan row), a field on `PlannedSet`, `plannedSetViolations`, the routine editor's plan row, and a `seedDraft` change. Until then, a duration exercise's first set is typed or stepped. This is an API and `@sin/core` spec first, then a small web one.
- **F2 — "Last time" per exercise** (17.1 non-goal, needs `lastPerformance`). It would seed a first set from history for every modality, and is the other way to remove the empty first set. Not requested here.

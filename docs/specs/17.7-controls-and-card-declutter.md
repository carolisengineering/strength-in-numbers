# Spec 17.7 — Controls and card declutter: segmented choices, one select, a Warm-up toggle, a quieter card (web)

**Status:** v0.2 (2026-11-09). Phase A implemented on branch `feat/spec-17-7a-segmented-select`; Phase B not started. §12 lists where Phase A departs from this text.

**Source:** the whole-app Impeccable critique of 2026-11-08 (23/40), step 4 of its agreed fix order. The owner's complaint, verbatim: "i don't like the size and shape of the dropdown menus when selecting options (like units)." She likes the large numbers and buttons and wants them kept.

**Kind:** UI (web only). **No API, `@sin/core`, migration, CSP or env change.** Two phases, each its own PR: **A** the two controls (`ui/Segmented`, `ui/Select`) and where they replace today's selects; **B** the logging screen's card (a Warm-up toggle, "More", Superset and Add note into Options, no modality line).

**Depends on:** Spec 17.4 shipping first (the 56 px Log button, the reserved status line, scroll to the panel after each log, `--session-bar-clearance`). Spec 17.0 (tokens, roles, `roles.test.ts`), 17.1 (the panel, Set options, `LinkToggle` placement), 10.0 / 10.1 (`LinkToggle`, regroup), 18.0 (edit screen shares `ExerciseCard` and `SetFields`).

**Design refs:** `apps/web/PRODUCT.md`, `apps/web/DESIGN.md` (teal is the one interactive color; "icons always beside a text label"; The Two Borders Rule), `apps/web/CLAUDE.md` (Workout screen "now", Planned sets, Visual identity).

## 1. Purpose, scope & non-goals

**Purpose.** Native selects are the one control on the logging screen that does not look like the rest of it. Verified in the code and the 2026-11-08 captures:

- A `<select>` is 44 px tall (`Field`'s `min-height`) beside 56 px Log, 48 px stepper buttons and 60 px number fields (the 01 capture's layout file: inputs 60, step buttons 48).
- In the entry panel a select is the panel's full width, 294 px at 390 px (390 − 32 screen padding − 32 card − 32 panel), to pick between "kg" and "lb". In the edit sheet the unit select is narrow (`.withUnit > .unit { width: auto }`), so the width complaint is the panel's.
- Corner radius differs: 6 px in `Field` (`--radius-sm`), 10 px on the picker's filters (`ExercisePicker.module.css` `.chip`, `--radius-md`) and on every button.
- kg / lb has four forms: the panel's select, the edit sheet's select (`UnitField`), `UnitToggle` (routine item sheet and plan rows) and the Profile select.
- Weight unit and set type sit behind "Set options". Opening it reveals the block under the bottom bar with no scroll (`SetFields` `EntryFields` only toggles state), so the tap can look like it did nothing. 17.4 D7 left this for this spec.
- A warm-up that is not in a plan reverts to Working on the next set (`draftFromSet` always sets `working`).

**In scope**
1. `ui/Segmented`, built from `ThemeSetting`'s strip (native radios), for 2–4 fixed options.
2. `ui/Select`, for long or variable lists: `appearance: none`, the same height and radius as `Field`, a chevron drawn from `ui/icons.tsx`, the native menu kept.
3. Replacing today's selects and `UnitToggle` with them (§6.1).
4. In the logging panel: a one-tap **Warm-up** toggle and a **More** button that reveals set type, weight unit and distance unit, scrolled clear of the bar.
5. On the live card: **Superset with previous / next** and **Add note** move into the card's Options; the modality line ("Weight × reps") goes.

**Non-goals**
- Steppers' size and labels, the panel label, rest, duration and distance steppers, the edit sheet's steppers (Spec 17.8).
- Undo, and protecting Delete set (Spec 17.5, a draft). This spec does not touch the edit sheet's action row.
- The docked panel (17.9, a draft; supersedes parts of this spec if built, §12).
- Converting a weight when the unit changes (D4).
- The edit screen's own superset toggles and its other controls (D6).
- Any API change. None is needed or deferred.

## 2. Acceptance criteria

### Phase A — the two controls

1. **Segmented.** `ui/Segmented.tsx` renders a `<fieldset>` with a `<legend>` and one native radio per option (the `ThemeSetting` pattern), takes `name`, `legend`, `options`, `value`, `onChange`, optional `hint` and `error`. Arrow keys move and select, Tab enters and leaves as one stop, the checked option is filled (`--color-selected` / `--color-on-selected`) and checked, never marked by color alone. Each option is at least `--tap-target-min` in both axes and the strip uses `--radius-md`.
2. **Narrow widths.** Options share equal columns; below a new token `--segment-min-width` (5rem) per option the strip wraps to more rows rather than clipping or scrolling. At 320 px, the four-option set type in the entry panel, the edit sheet and a routine plan row has no horizontal overflow and no clipped label (a harness measurement).
3. **No selection.** `value={null}` leaves every radio unchecked. `UnitToggle`'s `"mixed"` state keeps working through it (Spec 10.2 AC13).
4. **Select.** `ui/Select.tsx` renders a wrapper around a real `<select>` (the native menu stays) and a `ChevronDownIcon` added to `ui/icons.tsx`, `aria-hidden`, `pointer-events: none`. It forwards every select prop, including the `id`, `aria-describedby` and `aria-invalid` that `Field` injects. `appearance: none`; `min-height: var(--tap-target-min)`; `--radius-sm`; the 1 px `--color-border` boundary; the chevron in `--color-text`. No `data:` URL anywhere in CSS.
5. **One look.** A CSS scan finds the Select's and `Field`'s control radius and minimum height read the same tokens, and no `<select>` in `src/` is styled by a stylesheet other than `Select.module.css`, except the Field-level rule that styles inputs and textareas and `reset.css`'s `font: inherit`.
6. **Segmented sites.** These become `Segmented`, with unchanged values, ids' purpose and error wiring: weight unit and distance unit (panel and edit sheet), set type (panel More, edit sheet, routine plan rows), the timer format (`TimerFields`), Profile "Units", and `UnitToggle`'s two call sites (`ItemSheet`, `PlanRowList`). `UnitToggle.tsx` and its stylesheet are deleted.
7. **Select sites.** These become `Select`: Primary muscle and Equipment (`ExerciseFields`), the picker's Muscle and Equipment filters (inline width, still `aria-label`ed), Section (`SectionPicker`), Time zone, and the Hevy type (`MatchForHevySheet`). The Hevy sheet's bare `<select>` gets the same look.
8. **Theme.** `ThemeSetting` renders through `Segmented` with the same legend, hint, options and storage behavior; its tests pass unchanged except for imports.
9. **Unit change converts nothing.** With a weight of 100 typed, changing the unit lb → kg leaves the weight text at "100", sets `weightUnit: "kg"`, and the Log label reads "Log 100 kg" when the profile is lb (17.1 §6.6). Same for distance. The plan row and item sheet behave as before.
10. **Errors.** A server or client error on Profile "Units" shows under the Segmented with `role="alert"` and is named by the fieldset's `aria-describedby`.
11. **Roles and tokens.** `ui/roles.test.ts` `SIGNAL_ALLOWED` gains `ui/Segmented.module.css`, with the reason ("the checked option is a selection, as Theme was") in §12; `features/me/ThemeSetting.module.css` and `features/routines/UnitToggle.module.css` leave the list when they stop naming the selected tokens. `assert:css-tokens` passes: new tokens only in `tokens.css`.

### Phase B — the card

12. **Set options is gone.** The panel has a **Warm-up** button and a **More** button in one row, each at least `--tap-target-min`. No button named "Set options" remains.
13. **Warm-up toggle.** `aria-pressed` is true exactly when the draft's set type is warm-up. A tap sets the draft's type to warm-up, or back to working, through the ordinary `edit` action (so it is an edit like any other: the draft is touched and persisted, 06.5). Its accessible name starts with its visible text and names the exercise: "Warm-up for Overhead Press".
14. **A planned warm-up is already pressed.** When the next planned row is a warm-up, the toggle is pressed on mount and nothing is stored (D3 of 17.4: a prefill is not an edit).
15. **More.** The visible text is "More"; the accessible name is "More set options for {exercise}" (17.1 AC38 forbids a bare "More"); `aria-expanded` follows it. It reveals, inside the panel: Set type (`Segmented`, all four types), Weight unit when the modality has a weight, Distance unit when it has a distance. Set type's failure hint ("Couldn't complete a rep? Log 0 reps.") shows when Failure is chosen.
16. **The reveal is clear of the bar.** After More opens, the revealed block's bottom edge is above the session bar's top, by scrolling the block into view with `block: "nearest"`, no smooth behavior, and 17.4's `--session-bar-clearance` as the scroller's padding. Verified at 390 × 844 and 320 × 568.
17. **The panel names the type.** The panel's label suffix follows the draft's set type, not the plan's row ("Set 2 of 4 · Warm-up" after a tap, and "Set 2 of 4" after it is turned off), so a set that is not working is never invisible when More is closed. `setLabel` takes the draft's type.
18. **The toggle does not stick (D1, if confirmed).** After a log, the next draft's set type comes from `seedDraft` exactly as today (the plan's row, else working). 17.4 AC5's carry rule is unchanged.
19. **Superset in Options.** On the live screen, the current card's Options lists "Superset with previous" (when the card has a neighbor above in its segment) and "Superset with next" (below), as `LinkToggle`s, each with its pressed state, its refusal reason at the 8-member cap, and the same latch while a regroup is in flight (10.1 AC22). The toggles between cards are gone from the live screen; the bracket still draws through the joint. The regroup request sequence is unchanged. `LinkToggle` takes the neighbor's direction as a prop for its visible text.
20. **Add note in Options.** On both screens, "Add note" / "Edit note" is a button inside Options (same `aria-label` as today, "Add note for X"). The note text under the title stays. The note's sync state ("Not saved yet", "Couldn't save" with Discard) stays visible on the card header while Options is closed, and `failedRowRef` still lands on it, so the status line's "Show" works (06.2 AC14).
21. **No modality line while logging.** The live card does not render "Weight × reps". The edit screen's card and the collapsed row are unchanged.
22. **Shorter header.** In the 01 capture's fixture at 390 px, the distance from the current card's top to its panel's top is at least 60 px less than on main's capture (harness).
23. **Names and a11y.** No icon-only control is added. `axe` passes with Options open and with More open (the existing `a11y.test.tsx` sweeps).

### Must keep, docs and verification

24. **Regression guards.** Draft persistence (06.5), the 600 ms double-tap window, focus on the bar's button (17.1 AC29), one primary `Button` on the screen (17.1 AC39), offline queueing, and the edit screen's `Add set` all behave as before. Existing tests change only where this spec replaces a control (§10).
25. **Docs consistent.** The cross-doc updates in §12 are made.
26. **Every behavioral AC has a tagged test.** AC1–AC24 have at least one test named `17.7 ACn — …`, enforced by an `acTags.17-7.test.ts` scan (harness-only items excepted, §10).
27. **Visual review.** `pnpm --filter @sin/web run screens` captures the panel with More open and closed, a Segmented in the Profile and a routine plan row, and a Select in the picker, light and dark, 390 and 1280 px, and 320 × 568.
28. **Phone check (owner).** On the iPhone: change a unit and set type from More and confirm the block is fully visible each time; log a warm-up with the toggle; change the Profile unit; open the exercise picker's filters; link a superset from Options.

## 6. Behavior & logic

### 6.1 Which control

| Rule | Control |
|---|---|
| 2–4 fixed options that the user compares at a glance | `Segmented` |
| A long list, or one that varies with data | `Select` |

Segmented sites: weight unit (2), distance unit (4), set type (4), timer format (4: None, Set Timer, AMRAP, Time Cap), Profile units (2), plan-row type (4). Select sites: muscle, equipment, section, time zone, picker filters, Hevy type. A future control follows the table.

### 6.2 Warm-up and More

`EntryFields` keeps its own `optionsOpen` state, as today. The toggle calls `onChange("setType", …)`. No `dispatch(` appears in `SetFields.tsx` (17.1 `now.hygiene.test.ts`). After More opens, an effect scrolls the block with `scrollIntoView({ block: "nearest" })`; the scroller's padding is 17.4's `--session-bar-clearance`.

### 6.3 Options on the card

`ExerciseCard` gains optional `linkAbove` and `linkBelow` props, each `{ otherName, linked, refusal, disabled, onToggle }`, passed by `ActiveSession.renderRow` from the values it already computes for `LinkToggle`. The joint keeps drawing `SupersetBracket`. The edit screen passes neither, and keeps its own toggles (D6). The note row shows only the sync tags and the Discard button, and is rendered only when a tag is.

### 6.4 `Select` and the cascade

`Field`'s rule `.field :where(input, select, textarea)` and a Select's own class have equal specificity, and the earlier comment in `SetFields.module.css` (#203) shows that order was already a problem once. `Select.module.css` therefore styles the select as `.wrap .select` (two classes), so it looks the same inside or outside a `Field`.

## 12. Decisions & open questions

- ✅ **D1 — Segmented for fixed small sets, Select for long ones.** The owner's complaint is about the dropdown for a two-letter unit. A two-option choice that needs a menu, a tap and a re-read is slower than two visible buttons, and the strip already exists in Profile. **Rejected:** restyling the native select only (still a menu for kg / lb); a custom listbox (loses the platform's menu, costs accessibility work for no gain).
- ✅ **D2 — `Select` keeps the native menu.** Muscle, equipment and time zone lists are long; the platform's picker is the best control for them, and a custom one would need its own keyboard and screen-reader behavior.
- ✅ **D3 — The chevron is an inline SVG in a wrapper.** The CSP forbids inline styles, and a `data:` background would be a hard-coded value outside `tokens.css`. Hence `ChevronDownIcon` in `ui/icons.tsx`, beside the select's own text, which keeps the icons-beside-a-label rule.
- ✅ **D4 — A unit change converts nothing.** Plates are what they are: 100 on the bar stays 100 whichever unit the lifter says. The Log label already names a unit that differs from the profile (17.1 §6.6), and stays.
- ✅ **D5 — Superset goes where the card's other structure actions are.** A write that fires on one tap does not belong between two cards, above the Log button. In Options it takes two taps, which suits a rare action. Pressed state and refusal text are unchanged.
- ✅ **D6 — The edit screen keeps its own superset toggles.** Only the live screen has a bottom Log button to mis-tap. Add note moves on both screens because the card is shared.
- ✅ **D7 — `Select` uses `--radius-sm` (6 px), like `Field`.** (owner, 2026-11-08, accepted recommendation). A Select is a field, so it should match inputs; the picker's filters change from 10 px to 6 px. The alternative is 10 px to match buttons, which would make every form's select differ from its inputs.
- ✅ **D8 — Warm-up reveals only the two states; Drop and Failure live in More.** (owner, 2026-11-08, accepted recommendation). More shows the full four-way set type, so the toggle and More can never disagree: the toggle is pressed exactly when the type is warm-up.
- ✅ **D9 — The step buttons keep their icons for now.** Out of this spec: 17.8 replaces them with step text.
- **Roles allow-list reason (AC11).** `ui/Segmented.module.css` uses the selected tokens for the same reason `ThemeSetting` did: the checked option is a selection, which is the role teal already has.

**Settled (owner, 2026-11-08, accepted recommendation): each recommendation below was taken.**

1. ✅ **Should a Warm-up toggle stick to the next set? No (owner, 2026-11-08).** A forgotten toggle silently drops a real working set from PRs and volume (both count working sets only), while the cost of not sticking is one extra tap per warm-up in a ramp (three taps instead of two for three warm-ups). A planned ramp already follows the plan. If the phone check shows the extra tap annoys, make it stick within a run of warm-ups only (until the first set that is not one), and show it loudly in the label. AC18 assumes "no".
2. ✅ **`Select` radius, 6 px or 10 px** (D7). *Recommendation: 6 px.*
3. ✅ **Edit screen's superset toggles.** *Recommendation: leave them (D6)*; moving them too would make the two screens match at the cost of a larger change to a screen that has no mis-tap risk.

**Findings from the design review, checked against the code**
- **Confirmed:** select height 44 beside 56/48/60 px controls; the panel select is about 294 px wide (arithmetic from the card and panel padding, matching the 01 capture's 294 px "Set options" button; no capture opens Set options, so the select's own width is derived, not measured); the radius split; three forms of kg/lb, plus a fourth (the edit sheet's `UnitField`); Set options reveals under the bar; an unplanned warm-up reverts.
- **Narrowed:** the width complaint holds for the panel only; the edit sheet's unit select is already narrow.
- **Narrowed:** "Superset with next" does not sit beside the steppers. It sits in the gap between cards: above the current card when the previous one is collapsed, and below it (just above the Log bar) when a next row exists. It is still mis-tappable under the thumb, so the move stands, with a "previous" variant added because the toggle above the card reads "with next" from the other card's point of view.
- **Pre-existing, not part of the complaint:** the stepper's ± buttons are icon-only with an `aria-label`, which breaks "icons always beside a text label". 17.8 fixes it.

**Where Phase A departs from this text (2026-11-09).**
- AC2, §5: the panel at 390 px (294 px wide) shows set type 2 × 2, not four across as §5's sketch draws it. Four across there leaves about 64 px of text per option, and "Warm-up" broke at its hyphen ("Warm- / up") in the harness at a 4.5rem minimum. `--segment-min-width` stays the 5rem AC2 names, with 4 px of side padding per option, so the edit sheet and a routine plan row still show four across. A second token, `--segment-strip-min`, is the width four options need side by side; below it a four-option strip goes 2 × 2, never 3 + 1. The harness also fails an option whose text wraps.
- AC5: `ui/reset.css` also names `select` (its `font: inherit`), and sets no look; the scan allows it with `Field.module.css`.
- AC10: a group can't carry `aria-invalid`, so Profile's Units names its error through `aria-describedby` only.
- Choices the text left open: a checked option in a disabled strip (a locked timer) keeps a Teal Wash fill with ink text, so the choice still shows while it reads as locked; Enter on a Segmented radio does nothing (a browser would submit the form, where a select never did), and `EntryRow` logs on Enter only from a text field; the edit sheet's unit strip sits under its value inside the value's one `Field`, so a field error still follows both (#203).

## 1. Purpose, scope & non-goals

Turn the Spec 04.0 skeleton into something a person can use: a **CSS-Modules +
design-token styling foundation**, a small set of UI primitives, the thumb-zone
`AppShell` with bottom navigation, a `useSession()` convenience hook, a React
**error boundary**, and **one real vertical slice** — a **Profile** screen that
reads and `PATCH`es `/v1/me`. The slice exercises the API client, the RFC 9457
error contract, a TanStack Query mutation + cache update, and the form pattern end
to end, so later feature specs (06, 08, 10, 12) inherit a proven pattern.

> **First-principles note (styling, for a backend dev newer to the browser
> side):** the browser's CSS cascade + **custom properties** (`--name: value` on a
> selector, read as `var(--name)`) already *are* a theming engine. We put the
> whole design vocabulary — colour, spacing scale, type scale, radius, a minimum
> tap-target size — in one `tokens.css` on `:root`, and every component reads only
> `var(--…)`. **CSS Modules** means a file `Button.module.css` whose class names
> Vite rewrites to be unique, so styles are locally scoped with no naming
> convention to maintain and no runtime cost. This "styles are data, referenced by
> name" model is the same one React Native's `StyleSheet` uses, so the mental
> model ports if a native app is ever built (DESIGN §3.4). No CSS framework — see
> §12 Q11.

### In scope

- **`src/ui/tokens.css`** — CSS custom properties on `:root` (colour, `--space-*`,
  type scale, `--radius-*`, `--tap-target-min`), plus a `prefers-color-scheme`
  block. **`src/ui/reset.css`** — a minimal, boring CSS reset.
- **UI primitives** — `Button`, `Field` (label + input/select + error slot),
  `Screen` (page scaffold), `Spinner`, each `Component.tsx` + `Component.module.css`
  reading only tokens.
- **`<AppShell>`** — the protected layout element (replaces Spec 04.0's
  `AuthedPlaceholder` as the layout route's element): a `<header>` (section title +
  a profile affordance), a scrollable `<main>` with the route `<Outlet/>`, and a
  bottom-anchored `<nav>` driven by a declarative nav-item registry. Nav items:
  Workouts / History / Progress / Profile; the future-section items render
  "coming soon" stubs.
- **`useSession()`** — `{ user: Me, isAuthenticated, login(), logout() }`, wrapping
  `useAuth0` + `useMe`.
- **`<RootErrorBoundary>`** — a React error boundary around the routed subtree; a
  recoverable fallback ("Reload"), calls the `reportError()` seam.
- **Profile slice** — route `/app/profile`; `useMe()` for load; a form for
  `displayName` / `unitPreference` / `timezone`; `PATCH /v1/me` via a TanStack
  Query mutation; `422` → per-field inline errors; `200` → `queryClient.setQueryData`
  so the shell header reflects the new `displayName` with no reload.
- **Cross-doc edits** — DESIGN §3.2 (styling — already applied via Q11), §9 M0
  contents; `specs/README.md` row 04.1.

### Non-goals

- **Everything in Spec 04.0** — the package, config, Auth0 flow, API client,
  router, bootstrap gate, CI, deploy, CSP.
- **Any feature screen** — Spec 06 (logging + picker), 08 (history / progress),
  10 (routines), 12 (account export/delete UI). Nav items for those render
  "coming soon" stubs here.
- **A component library / Storybook / visual-regression tooling** — four
  primitives, styled by hand, is the v1 surface. Revisit if the primitive set
  grows past ~a dozen.
- **Theming / user-selectable themes** — only `prefers-color-scheme`. A theme
  switcher is post-v1.
- **Client-side `Intl` timezone validation** — the server validates the IANA name
  and returns `422`; the client does not re-implement it.
- **`localStorage` persistence of the query cache** — R1 / M4.

## 2. Acceptance criteria

Behavioural criteria (AC2–AC9) each get ≥1 Vitest/RTL test naming their number
(`describe("AC4 — …")`). AC1 is a review + lint/grep criterion — see §10. AC10 is
the coverage-of-criteria check.

1. **Styling foundation.** A single `src/ui/tokens.css` defines the colour /
   `--space-*` / type-scale / `--radius-*` / `--tap-target-min` custom properties
   on `:root`; every `*.module.css` in `apps/web` references design values only as
   `var(--…)` (no hard-coded hex / px for colour, spacing, or radius — lint/grep);
   `apps/web/package.json` `dependencies` contains no CSS framework (no `tailwindcss`,
   `bootstrap`, `@mui/*`, `styled-components`, `@emotion/*`, etc.).
2. **Thumb-zone shell.** `<AppShell>` renders a single bottom-anchored `<nav>`
   whose stylesheet rule text sets `min-height` / `min-width` on each interactive
   nav target to `var(--tap-target-min)` and sets `padding-bottom` to a value
   containing `env(safe-area-inset-bottom)`. `--tap-target-min` resolves to `44px`
   in `tokens.css`. (Real computed geometry + 320px no-horizontal-overflow is
   verified in the M1 e2e — §10.)
3. **Shell mounts only when authed + bootstrapped.** `<AppShell>` is the element
   of the protected layout route, so it renders only after `BootstrapGate`
   resolves `200 /v1/me`; an unauthenticated visit to `/app/profile` never mounts
   `<AppShell>` (redirect handled by Spec 04.0 `ProtectedRoute`, re-asserted
   here). The `<header>` shows the current `displayName` (or `email` fallback).
4. **`useSession()` surface.** `useSession()` returns `{ user, isAuthenticated,
   login, logout }`; `user` is the `MeSchema`-typed body from the `["me"]` query;
   `login()` calls `loginWithRedirect` with the current path as `returnTo`;
   `logout()` calls Auth0 `logout` with `returnTo: window.location.origin`.
5. **Profile loads current values.** `/app/profile` renders the `displayName`,
   `unitPreference` (`<select>` populated from `UNIT_PREFERENCE_VALUES` with the
   current value selected), and `timezone` from `GET /v1/me`; while the query is
   pending it shows `<Spinner/>`, not an empty form.
6. **Profile saves.** Submitting the form issues `PATCH /v1/me` with only the
   changed fields (JSON body validated against `UpdateMeSchema` shape); a `200`
   calls `queryClient.setQueryData(["me"], body)` and the `<AppShell>` header
   reflects the new `displayName` **without a reload or refetch**. `displayName`
   cleared to empty submits `null`.
7. **Profile validation errors.** A `422` `validation-error` response maps each
   `errors[].path` to an inline message under the matching `<Field>`; the
   submitted value is **not** echoed back into the message; fields without an
   error entry are left untouched; a non-validation error (`5xx` / network) shows
   a single form-level message carrying the `requestId`.
8. **Error boundary.** A render error thrown anywhere in the routed subtree is
   caught by `<RootErrorBoundary>`, which shows a recoverable fallback with a
   "Reload" action (not a blank page) and calls the `reportError()` seam once with
   the error.
9. **Primitives behave.** `<Field>` associates its `<label>` with the control
   (`htmlFor` / `id`) and renders `errors` text with `role="alert"` /
   `aria-describedby`; `<Button>` reflects `disabled` and a `busy` state
   (`aria-busy`, not clickable while busy); `<Screen>` renders a titled region
   (`<h1>` / labelled landmark).
10. Each behavioural criterion (2–9) has ≥1 committed test tagged with its
    number; 1 is verified by review + lint/grep per §10.

## 5. Screens & flows

*(UI spec. API surface consumed: Spec 01 §5 — `GET /v1/me` (via 04.0 `useMe`),
`PATCH /v1/me`, and the RFC 9457 error bodies.)*

### Routes added

| Path | Auth | Screen | Notes |
|---|---|---|---|
| `/app` | protected | `<AppShell>` → `AppIndex` | `AppIndex` = a short "welcome" body until Spec 06 adds the real default. |
| `/app/profile` | protected | `<AppShell>` → `ProfileScreen` | The vertical slice. |
| `/app/workouts`, `/app/history`, `/app/progress` | protected | `<AppShell>` → `ComingSoon` | Real screens in 06 / 08 / 10. |

`<AppShell>` becomes the `element` of the protected layout route defined in 04.0
§6.7 (replacing `AuthedPlaceholder`).

### Shell & one-handed layout

- `<AppShell>`: `<header>` (section title + a profile/menu affordance showing
  `displayName`), a scrollable `<main>` holding the `<Outlet/>`, and a `<nav>`
  fixed to the bottom edge. Bottom nav because the reachable zone on a phone held
  one-handed is the lower third of the screen (DESIGN §1.2).
- Nav registry: `NAV_ITEMS: { to, label, icon, comingSoon? }[]` — Workouts /
  History / Progress / Profile. Each target is `min-height`/`min-width`
  `var(--tap-target-min)`, spaced by `var(--space-*)`. `padding-bottom` on the
  `<nav>` includes `env(safe-area-inset-bottom)` so it clears the iOS home
  indicator.
- Breakpoints: mobile-first. Base styles target a 320–430px column; a single
  `@media (min-width: 48rem)` tier moves the nav to the side and caps `<main>`
  width for tablet/desktop (real desktop polish is later specs). All layout in
  `rem` / `%` / `clamp()` — no fixed px widths that could overflow at 320px.

### Profile screen (the slice)

- Load: `useMe()` (from 04.0). Pending → `<Spinner/>`.
- Fields:
  - `displayName` — text, ≤ 80 chars, clearable → submits `null`.
  - `unitPreference` — `<select>` from `UNIT_PREFERENCE_VALUES`.
  - `timezone` — text; the server validates the IANA name and returns `422` on a
    bad one.
- Submit → `useMutation(() => api.patch("/v1/me", body, MeSchema))` where `body`
  is only the changed fields:
  - `200` → `queryClient.setQueryData(["me"], body)`; a success affordance; the
    `<AppShell>` header re-renders from the updated query.
  - `ApiError.isValidation()` → distribute `errors[]` to `<Field>`s by `path`.
  - other `ApiError` → one form-level message showing `err.requestId`.

### Terminal / empty states

- Reuses Spec 04.0's `AuthError` / `AccountDeleted` / `RetryScreen` / `NotFound`
  — this spec only restyles them against the tokens (no behavioural change).

### 6.2 Styling tokens

`src/ui/tokens.css` on `:root` — the whole design-system foundation:

```css
:root {
  --color-bg: #0b0c0f; --color-surface: #16181d; --color-text: #f2f3f5;
  --color-accent: #4f7cff; --color-danger: #ff5c5c; --color-muted: #9aa0aa;
  --space-1: 0.25rem; --space-2: 0.5rem; --space-3: 0.75rem; --space-4: 1rem;
  --space-6: 1.5rem; --space-8: 2rem;
  --font-size-sm: 0.875rem; --font-size-md: 1rem; --font-size-lg: 1.25rem;
  --font-size-xl: 1.75rem;
  --radius-sm: 6px; --radius-md: 10px;
  --tap-target-min: 44px;
}
@media (prefers-color-scheme: light) { :root { /* light overrides */ } }
```

Components use `*.module.css` (Vite hashes class names → local scope) and read
only `var(--…)`. No design values hard-coded in component CSS (AC1, lint/grep).
CSS Modules emit external hashed `.css` — keeps `style-src 'self'` (Spec 04.0
§6.6).

### 6.3 `useSession()`

```ts
export function useSession() {
  const { isAuthenticated, loginWithRedirect, logout } = useAuth0();
  const { data: user } = useMe();                 // 04.0
  const loc = useLocation();
  return {
    user,
    isAuthenticated,
    login: () => loginWithRedirect({ appState: { returnTo: loc.pathname + loc.search } }),
    logout: () => logout({ logoutParams: { returnTo: window.location.origin } }),
  };
}
```

### 6.4 Error boundary

`<RootErrorBoundary>` — a class component (`getDerivedStateFromError` +
`componentDidCatch`): render fallback = a `<Screen>` with the message "Something
broke" and a "Reload" button (`() => window.location.reload()`);
`componentDidCatch(err)` calls `reportError(err, { boundary: "root" })` exactly
once (guarded so a re-render loop does not spam the seam). It wraps the
`<RouterProvider>` subtree so a thrown render error anywhere below it is caught.
It does **not** catch async errors in event handlers or queries — those surface as
`ApiError` and are handled in-screen.

### 6.5 Profile mutation & cache

- The mutation `queryFn` returns the parsed `Me` (04.0 client `schema.parse`).
- On success: `queryClient.setQueryData(["me"], body)` — a direct cache write, no
  refetch, so the header updates synchronously (AC6).
- On `ApiError`: `err.isValidation()` → build a `Record<fieldName, message>` from
  `err.errors` keyed by the last segment of `path`; anything else → form-level
  message with `err.requestId`.
- The form tracks which fields are dirty; the `PATCH` body includes only dirty
  fields. An empty `displayName` input serialises as `null` (explicit clear), not
  omitted.

### 6.6 Coming-soon stubs

`ComingSoon` renders a `<Screen title={section}>` with one line ("Coming with the
next release"). The nav item stays visible (`comingSoon: true` dims it and shows a
small marker) so the shell's information architecture is stable as later specs
fill sections in.

## 7. Security & privacy

- **PII in the shell.** `displayName` / `email` are rendered (the user's own
  data). They must never be put into `X-Request-Id`, `track()` event names/props,
  or `reportError()` metadata (DESIGN §8.1). `<RootErrorBoundary>` passes only the
  `Error` object and a static `{ boundary }` tag to `reportError()`.
- **Validation-error hygiene.** The `422` handler renders `errors[].message` as
  the API sent it (already value-free per Spec 01 / 03.0) and **never** echoes the
  user's submitted value into the error text (AC7) — avoids reflecting attacker
  input if `displayName` ever contained markup.
- **No new network origins.** Profile talks to `PATCH /v1/me` on the same API base
  URL already in the CSP `connect-src` (Spec 04.0 §7). No CSP change.
- **No secrets, no tokens** touched here — auth is entirely Spec 04.0's client.
- **Output encoding.** All user data is rendered through React (auto-escaped);
  no `dangerouslySetInnerHTML` anywhere in `apps/web` (lint rule).

Full token-storage / CSP / auth reasoning: Spec 04.0 §7.

## 9. Observability

- **`reportError()`** — called by `<RootErrorBoundary>` (once per caught error).
  No-op until Spec 13.
- **`track()`** — left unused by this spec beyond an optional `profile_saved`
  event with **no** property values (event name only), to prove the seam. No-op
  until Spec 13.
- **`X-Request-Id`** — the Profile form surfaces `ApiError.requestId` on a
  form-level error so a user-reported save failure correlates with an API log line
  (Spec 04.0 §9, DESIGN §8.1).

- **No new service, no migration, no API change, no env var.** Ships as part of

  confirm the header updates without a reload; confirm no CSP console violation.

## 12. Decisions & open questions

### Resolved

- ✅ **Q11 — Styling: CSS Modules + CSS custom-property tokens, no framework.**
  From first principles the cascade + custom properties already are a theming
  system: `tokens.css` on `:root` is the design system, `*.module.css` gives
  locally-scoped styles with zero runtime and no naming convention to maintain,
  and the "styles are data" model ports to React Native's `StyleSheet`. Rejected:
  **Tailwind** — strong productivity + market signal, but a second styling
  language layered on CSS, and the developer is explicitly newer to frontend
  (CLAUDE.md); the DESIGN ethos (Fastify over Nest, SPA over Next, "smallest
  concept surface for learning") points the same way. Also rejected: **CSS-in-JS**
  (runtime cost on mid-range gym phones, React 19 friction) and **zero-runtime
  CSS-in-TS** (vanilla-extract / Panda — more tooling than a solo v1 needs).
  Revisit Tailwind only if styling velocity becomes a measured bottleneck.

- ✅ **Q16 — One vertical slice only (Profile).** The frame plus `GET`/`PATCH
  /v1/me` proves the client, the error contract, a TanStack Query mutation +
  cache write, and the form pattern end to end without bleeding into Spec 06's
  scope. Other nav sections render "coming soon" stubs so the information
  architecture is stable for later specs.

- ✅ **Q22 — `AppShell` + bottom-nav live in 04.1, not 04.0.** The thumb-zone
  criterion (tap-target sizing, safe-area inset) is only verifiable against the
  token system, which this spec introduces — so the styled shell and its nav
  registry belong here. Spec 04.0's protected area renders a minimal placeholder
  until this spec swaps in `<AppShell>` as the layout route's `element`. Both
  specs are M0, so Spec 06's dependency on "the shell" is satisfied within the
  same milestone.

### Open

- None. (The cold-load / `useRefreshTokensFallback` / tab-eviction items —
  Q19–Q21 — are resolved in **Spec 04.0 §12** and never affected the Profile
  slice.)

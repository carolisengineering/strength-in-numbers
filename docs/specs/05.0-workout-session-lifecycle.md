## 1. Purpose, scope & non-goals

Ship the **session lifecycle** of workout logging: the `workout` and
`workout_exercise` tables, the endpoints that start, resume, edit, finish and
delete a workout session and that add, reorder and remove exercises within it,
and the `@sin/core` types those endpoints need. This is the first of three
specs that split the roadmap's Spec 05 (05.0 session lifecycle, 05.1 set
logging, 05.2 rate limiting and write quotas), because the original scope
bundled several work sessions' worth of change. It also fixes the two rules
every later logging feature leans on: workout creation is idempotent under
retry (DESIGN §6), and `local_date` is derived once, at write time, from the
client's own offset (DESIGN §4.0).

### In scope

- The `workout` and `workout_exercise` tables, in migration
  `0005_create_workout_session`.
- The session lifecycle endpoints: create, read the active session, read by
  id, update (including finish), delete; add, update (reorder) and delete a
  workout exercise.
- Workout-creation idempotency via `client_generated_id`, and the
  one-in-progress-session-per-user rule.
- The calendar-field rules (`local_date` / `tz_offset_minutes`): how they are
  supplied, derived and stored.
- The `@sin/core` additions those need: `WorkoutId` / `WorkoutExerciseId`,
  `WORKOUT_SOURCE_VALUES`, the workout DTOs, and a new `time.ts` module of pure
  calendar helpers.

### Non-goals

- **`set_entry` and everything measure-shaped** — the table, per-modality
  validation, and the finish integrity rule ("a working set needs at least one
  measure") — are **Spec 05.1**. 05.0's finish transition only sets
  `ended_at`.
- **Rate limiting and per-user write quotas** are **Spec 05.2**, which also
  closes 03.2's open D20 (connection-pool blast radius) and D21 (unbounded
  storage growth via create/delete cycling). 05.0 ships no write throttle.
- **The paginated history list and all PR/progress work** are **Spec 07**.
  There is deliberately no `GET /v1/workouts` list here, and finishing a
  workout does not write PRs; 07 adds the PR recompute to the finish
  transition and backfills workouts finished before it ships.
- **`routine_id` and `superset_group`** semantics are **Spec 09**. Neither
  column is created here (see §4 and §12).
- **The logging UI** — active-session screen, exercise picker integration,
  resume flow — is **Spec 06**.

## 3. Dependencies & exposed interface

### Needs

- **Spec 01** — `buildApp`, the RFC 9457 error contract, the auth plugin's
  `request.user`, `assertOwned` (`repositories/user.ts`), the UUIDv7
  convention, and the Testcontainers integration harness.
- **Spec 02** — `@sin/core`, `brandId()`, and the `MeSchema` DTO pattern.
- **Spec 03.0** — the Zod route-schema convention, the type provider, and the
  OpenAPI emit plus its drift check.
- **Spec 03.1** — the `exercise` table, `exerciseRepository.findVisibleById`,
  and `ExerciseId`.

No new runtime or dev dependencies.

### Provides — stable surface (Specs 05.1, 06, 07, 11 consume this)

| Export | Shape | Consumed by |
|---|---|---|
| `workout` and `workout_exercise` tables | Postgres tables (migration `0005`) | 05.1 (`set_entry` FKs to `workout_exercise`), 07 (history, PRs), 11 (export, purge) |
| `POST /v1/workouts`, `GET /v1/workouts/active`, `GET /v1/workouts/{id}`, `PATCH /v1/workouts/{id}`, `DELETE /v1/workouts/{id}`, `POST /v1/workouts/{id}/exercises`, `PATCH /v1/workout-exercises/{id}`, `DELETE /v1/workout-exercises/{id}` | eight endpoints | 06 (session start, resume, finish, exercise add/reorder/remove) |
| `WorkoutSchema`, `WorkoutExerciseSchema`, `WorkoutDetailSchema`, `CreateWorkoutSchema`, `UpdateWorkoutSchema`, `AddWorkoutExerciseSchema`, `UpdateWorkoutExerciseSchema` (+ inferred types), `WorkoutId`, `WorkoutExerciseId`, `WORKOUT_SOURCE_VALUES` (`@sin/core`) | Zod DTOs, branded ids, frozen constant | 05.1 (set DTOs build on the ids), 06 (form validation, client types) |
| `localDateFor`, `offsetMinutesForZone` (`@sin/core`, new `time.ts`) | pure functions | 05.1 (any calendar-derived field), 07 (history bucketing) |
| `workoutRepository` (`apps/api/src/repositories/workout.ts`) | repository interface + Prisma factory | 05.1 (set writes reuse its ownership checks), 07 (history reads, PR recompute) |

**Consumers must note:**
- The purge-ordering obligation that 03.1 §3 and 03.2 §3 hand to Spec 05 —
  `workout_exercise.exercise_id` versus `exercise.owner_user_id ON DELETE
  CASCADE` — is **discharged here**: `workout_exercise.exercise_id` is
  `ON DELETE CASCADE` (§4), so an account purge cannot deadlock on it.
- 05.1 extends the finish transition with the working-set integrity rule, and
  07 adds the PR recompute to the same transaction. Neither is built here;
  §6 names the seam for each.
- 05.0 ships no write throttle. 03.2's D20 and D21 stay open until 05.2.

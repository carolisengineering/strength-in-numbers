# Spec 17.11 — Exercise page and routine item sheet: chart first, one line per planned set (web)

**Status:** Phase A implemented (PR #311, merged 2026-11-12). Phase B built (branch `feat/spec-17-11b-plan-rows`, 2026-11-12).

**Source:** the whole-app Impeccable critique of 2026-11-08 (23/40). The owner has asked for the specs of the whole fix order before any building. The two decisions below (D1, D3) need the owner's OK before building.

**Design refs:** Spec 18.2 (the exercise page: AC21 details, AC23 progress body, AC34 actions, AC43, AC54 focus); Spec 08.1 (the chart); Spec 08.0 AC18 (the records line); Spec 10.2 AC13–AC17 (plan rows, `planRows.ts`, P1, P6); Spec 17.6 D6 (record labels); Spec 17.7 (set type becomes a `Segmented` in a plan row); Spec 17.10 (the item sheet's Done moves to the bottom row); `apps/web/DESIGN.md` ("Collapsed exercise row", "Workout menu": inline reveal, no popover).

## 1. Purpose, scope & non-goals

**Purpose.** Two screens put their reason for existing below a wall of text and buttons. The exercise page spends 220 to 290 px on a details table, a paragraph and buttons before the chart's controls, so on a 390 × 844 phone the nav cuts the chart in half (screenshots 15, 16, 81). The routine item sheet shows a five-set plan as 37 controls and about 1,700 px of scrolling, three Move/Remove buttons per set (screenshot 09).

**What was checked.**
- **Source table, built-in paragraph, Make your own copy before the chart: right.** `ExerciseScreen` renders `ExerciseDetails`, then `ExerciseActions`, then `ExerciseProgressBody`. In 81 (an own copy) the chart starts at about y = 590 and the nav cuts it at y = 778, hiding its bottom and the x-axis; in 15 (a built-in, with the paragraph) the Metric and Range controls alone begin at y = 459.
- **Records at the end, repeating the name: right.** `RecordsSection` renders `recordLine(record)` for each record: "Bench Press — Heaviest weight 82.5 kg (was 80 kg)" on a page titled "Bench Press".
- **"Open workout" is 24 px tall: right, and the cause is a CSS slip.** In `ExerciseProgressBody.module.css` the rule `.link, .sessions { display: flex; … }` shares one selector list, so `.link` has no `min-height`. The screenshot harness already lists it ("Open workout" 104 × 24) on 36 captures.
- **37 controls: right.** Five sets × (Type, Reps, Weight, Move up, Move down, Remove) = 30, plus kg and lb, Add set, Rest, Notes, Done, Close.

**In scope.**
- Phase A: the exercise page's order, the details disclosure, the records rows, the "Open workout" target.
- Phase B: the item sheet's plan rows.

**Non-goals.**
- The workout summary's records (Spec 17.6) and History's trophy.
- The chart itself, its metric and range controls, and desktop width (Spec 17.12, which makes the chart text stop scaling with the container).
- The sheet's action row (Spec 17.10), set-type control (17.7).
- The routine editor's other sheets and the quick-line mode.
- Any API, schema or `@sin/core` change. **No API change is needed.**

## 2. Acceptance criteria

### Phase A — the exercise page

1. **The order.** For an exercise with logged sets, the page reads in this DOM and visual order: back link, `h1`, the polite status line and any error notice, the Metric and Range controls, the readout row, the chart, the sessions list, "Personal records", then the details disclosure.
2. **The chart is visible on arrival.** At 390 × 844 the chart's bottom edge is above the nav's top edge, for a built-in exercise, an own exercise (with its Edit and Delete), and a copy. A harness measurement (jsdom has no layout).
3. **One disclosure for what rarely changes.** The source/type/muscle/equipment rows, the built-in note and Make your own copy (built-in) or Edit and Delete exercise (own exercise or copy) sit inside one native `<details>` whose summary reads "Exercise details", at least `--tap-target-min` tall. It is closed when the exercise has logged sets.
4. **Open when there is nothing else.** For a never-logged exercise the disclosure is open, because it is the page. A deleted exercise (history kept) keeps today's page with no disclosure.
5. **Messages stay visible.** The status line ("Saved.", "Your copy is ready.", "Already deleted.") and the Delete failure notice render above the chart, outside the disclosure, so a result is seen even if the lifter has closed it.
6. **18.2 behavior unchanged.** Edit, Make your own copy and Delete work as before, including the copy's redirect and `{ notice: "copied" }`, focus on the title after a copy (AC43), and focus back on Edit or Delete exercise after their sheet or dialog closes (AC54). Opening Edit while the disclosure is open leaves it open.
7. **Records rows.** Each record is one row: the label, the value (ink, `--font-weight-figure`), and a muted "was 80 kg" or "First record". The exercise's name does not appear. Rows keep today's order (`sortRecords`) and set-volume records stay in this list. The heading stays brass; nothing else is.
8. **Wording follows the label table.** Labels come from `recordLabel` / `formatRecordByType` as they are when this ships, so if Spec 17.6 D6 has landed ("Est. 1-rep max") the page says that, and if not, today's label. Nothing here depends on 17.6 shipping first.
9. **A row reads as a sentence to a screen reader.** "Heaviest weight: 82.5 kg, was 80 kg". The list is a `ul`.
10. **"Open workout" is a 44 px target.** The link's box is at least `--tap-target-min` in both axes, with the same text and destination, at 390 and 320 px wide, without overlapping the readout. The harness's small-target list is empty for screenshots 15, 16, 75 and 81.

### Phase B — the item sheet's plan rows

11. **One line per set.** In plan mode each planned set is a collapsed row: a button, at least `--tap-target-min` tall, whose text is the set's summary, "1 · Warm-up · 8 reps · 40 kg". Which parts show follows the exercise's type, as the fields do now (`showReps`, `showWeight`); a timed exercise shows the type only. An empty field shows "–". Text the lifter typed that does not parse is shown as typed.
12. **Opening a row.** A tap opens that row in place: the Type, Reps and Weight fields (unchanged labels: "Set k type", "Set k reps", "Set k weight") and Move up, Move down and Remove. The summary button has `aria-expanded` and `aria-controls` (*Phase B build, 2026-11-12: `aria-controls` is set only while the row is open, because a closed row's panel is not drawn and the attribute would name a missing element*). One row is open at a time; opening another closes the first with no loss of what was typed. Plan mode opens with the first row open when the plan has one row or was just entered from the quick line, and with all rows closed when an existing plan is loaded.
13. **No operation is lost.** Everything Spec 10.2 AC13 offers is still there and behaves the same: add a set (disabled at 20 with "Up to 20 sets"), remove (disabled on the only row with "A plan needs at least one set"), move (disabled at the edges), the kg / lb toggle with its mixed-unit state ("Mixed units — pick one to use for all sets"), each row's own unit shown while mixed, row errors beside their fields, and Back to the quick line (or the "Sets differ" line).
14. **Reasons in words.** A disabled Move up on the first row reads "First set" and a disabled Move down on the last reads "Last set", beside the button, as `aria-describedby` text (the live card does the same, Spec 10.3 AC17). This replaces 10.2's "self-evidently positional" for the edge buttons. Remove and Add set keep their texts.
15. **Control count.** For a five-set plan of a weight × reps exercise, with every row closed, the sheet holds at most 12 tabbable controls (five summaries, kg, lb, Add set, Rest, Notes, Done, Close); with one row open, at most 18. Today it is 37. *Amended (Phase B build, 2026-11-12): counted as tab stops, as a keyboard meets them. Since Spec 17.7 kg and lb are one radio group, one stop, and since Spec 17.10 Cancel is one more, so twelve is five summaries, the unit group, Add set, Rest, Notes, Close, Cancel and Done, on a plan that shows "Sets differ". A uniform plan has one more, Back to the quick line. One open row adds its type group, Reps, Weight, Move up, Move down and Remove: 18.*
16. **Errors open the row.** Done with an invalid row keeps the sheet open (10.2 AC16), opens the first invalid row, and moves focus to its first invalid field. A collapsed invalid row's summary ends "Check this set" in words, not by color alone.
17. **Focus survives.** After Move up or Move down, focus stays on the pressed button; if it becomes disabled at an edge, focus goes to the row's summary button. After Remove, focus goes to the summary button of the row that now holds that place (the previous one if it was last). After Add set, the new row is open and focus is on its first field.
18. **The data path is untouched.** `planRows.ts` has no diff. The request body for every shape (a plan, a collapsed quick line, mixed units, a timed exercise) is byte-identical to today's (10.2 AC17's round trip), and Done on an untouched sheet still does not arm the leave guard (10.0 AC1).
19. **Quick-line mode is unchanged.** Sets / Reps / Weight and "Plan each set" look and behave as now.
20. **Accessible names.** Each open row is `role="group"` named "Set k"; each field keeps its present accessible name; each Move and Remove button keeps "Move up, set k" and so on.
21. **No new values.** Only existing tokens; no new color. `assert:css-tokens` and `roles.test.ts` pass untouched.

### Docs and verification

23. **Every behavioral AC has a tagged test.** AC1–AC21 (except the harness ones, AC2 and AC10's measurement) have ≥1 test named `17.11 ACn — …`, enforced by an `acTags.17-11.test.ts` scan.

## 6. Behavior & logic

### 6.1 Page order

`ExerciseScreen` renders, for a found exercise: status line and failure notice; then `ExerciseProgressBody` (or the never-logged line); then `<details>` holding `ExerciseDetails` and `ExerciseActions`. `ExerciseActions` keeps its refs (`deleteRef`, the edit ref). A `{ notice: "copied" }` arrives on a new page whose disclosure is closed; the status line outside it announces the copy.

### 6.2 Records rows

`recordParts(record, pref)` returns `{ label, value, was }` and `RecordRows` draws the parts. A first record has `was: null` and shows "First record". Dividing by parts keeps one source for the text. *Amended (Phase A build, 2026-11-12): `recordLine` was removed rather than rebuilt on the parts; its only production caller was `RecordsSection`, and `RecordRows.test.tsx`'s `recordParts` table took over its tests.*

### 6.3 `planRowSummary`

```ts
planRowSummary(row: PlanRowText, { n, showReps, showWeight, unit }): string
// "1 · Warm-up · 8 reps · 40 kg"   n is the set's place; reps shown as typed, "reps" after any value that parses ("6-8 reps")
// weight unit: the sheet's unit, or the row's own while mixed
// no reps and no weight shown (timed exercise): "2 · Working"
```

Pure, no formatting of numbers beyond what `planRows.ts` already stored as text.

### 6.4 Open row state

`PlanRowList` holds `openKey: string | null`. It is local (the sheet owns the rows; this is view state). Done's validation, on failure, sets `openKey` to the first invalid row's key and focuses the first invalid field through the existing error wiring. Move keeps the key (rows move, the key does not). Focus after Move and Remove follows AC17 through refs keyed by row key.

## 12. Decisions & open questions

- ✅ **D1 — Chart first; everything about the exercise itself goes under "Exercise details" (owner, 2026-11-08, accepted recommendation).** **Rationale:** the page exists to show progress (PRODUCT principle 3); the table and the paragraph are read once. **Cost:** Edit, Delete exercise and Make your own copy need one more tap. They are rare. **Rejected:** moving only the actions (the table still pushes the chart down); leaving the table and shrinking it to one line (a Source/Type/Primary muscle line wraps on 320 px).
- ✅ **D2 — Records stay below the chart and above the disclosure (owner, 2026-11-08, accepted recommendation).** A lifter looking at progress wants the best numbers next to the line. **Rejected:** records before the chart (the chart is the page's figure, 17.0).
- ✅ **D3 — A planned set is a collapsed line that opens in place; one open at a time (owner, 2026-11-08, accepted recommendation).** **Rationale:** the review asked for a line per set with Move and Remove behind a per-set control, and this app has no popover (DESIGN.md): the established pattern is the inline reveal. The collapsed line is the same shape as a collapsed exercise row on the workout screen. **Cost:** editing a set takes a tap first; editing five weights takes five. **Rejected:** (a) always-open single-line rows with Type, Reps, Weight and an Options button — at 390 px the four controls and a labeled button (icons never stand alone) need about 420 px of 358, so the row would wrap to two lines anyway and keep 20 fields on screen; (b) a read-only summary list with a separate edit screen — more navigation for the common case.
- ✅ **D4 — The chart and its controls are unchanged here.** Their desktop sizing is Spec 17.12.
- ✅ **D5 — `planRows.ts` is not touched.** The review's constraint that the screen loses no operation is met by leaving the pure layer alone and testing the same cases through the new view.
- ✅ **D6 — Edge reasons are written out.** The live card already says "Last exercise in this section"; a Move button that is dead and silent is the one pattern 10.2's own principle (P6, disabled controls say why) forbids.

**Settled (owner, 2026-11-08, accepted recommendation): each recommendation below was taken.**
1. D1 and D3 as proposed. Recommendation: accept both; D3's alternative (a) is the one to reconsider if editing every set of a long ramp feels slow in the phone check.
2. Should "Exercise details" be open by default on a built-in exercise, where the note and Make your own copy are the only action? Recommendation: no; keep it closed, as the rule is about the page, not the exercise kind.

**Deferred follow-ups.** Desktop: details beside the chart rather than under it (17.12 Phase C). Disabled-reason text on the live card for an unsectioned workout (17.13, same pattern).

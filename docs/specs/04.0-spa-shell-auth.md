## 1. Purpose, scope & non-goals

Stand up `apps/web` as the deployable **Vite + React + TypeScript SPA** and prove
the browser end of auth: a user completes the Auth0 Authorization Code + PKCE flow
in a mobile browser, the app acquires an access token held **in memory only**,
calls `GET /v1/me` (which provisions the `user` row server-side per Spec 01 §6.2),
and renders an authenticated placeholder. This spec ships the *plumbing and the
frame*; Spec 04.1 adds the design system and the first real screen.

> **First-principles note (for a backend dev newer to the browser side):**
> Our app is a **single-page application**: the server sends one near-empty
> `index.html` plus a JavaScript bundle, and all navigation/rendering happens in
> the browser. There is no server-rendered HTML and **no server-side session** —
> the browser itself holds the credential. Auth is **OpenID Connect
> Authorization Code with PKCE** ("pixy"): the app redirects to Auth0's hosted
> login page, the user authenticates there, Auth0 redirects back to our
> `/callback` URL with a one-time `code`, and the SDK exchanges that `code` (plus
> a locally-generated secret proof, the "code verifier") for tokens. PKCE exists
> precisely so a public client that *cannot keep a secret* — any browser app —
> can still do the exchange safely; there is **no client secret** anywhere in
> this spec. The access token is a short-lived JWT the API already knows how to
> verify (Spec 01 §6.1); we attach it as `Authorization: Bearer` on every `/v1`
> request. Where that token *lives* in the browser is the load-bearing security
> decision here — see §7 and §12.

### In scope

- **`apps/web` package** (`@sin/web`) — Vite 5 + React 19 + TypeScript, wired into
  the pnpm workspace and `pnpm -r build`; imports `@sin/core` by package name
  (first real consumer-side resolution of Spec 02's `exports` map). First non-Node
  `tsconfig` in the repo; a browser-globals ESLint block.
- **Config** — `import.meta.env` (`VITE_*`) parsed by a Zod schema at module load;
  a missing/blank required var throws before React mounts and renders a static
  "misconfigured" page.
- **Auth0 browser flow** via `@auth0/auth0-react` (DESIGN §5.1): `loginWithRedirect`
  / `logout`, the `/callback` redirect handler, access-token acquisition, and
  **silent renewal via refresh-token rotation** (`useRefreshTokensFallback: false`,
  §12 Q19). Token cache location is **memory only** (§7, §12). Auth0's in-memory
  refresh-token **Web Worker is self-hosted** (`workerUrl` → a same-origin file)
  so the CSP keeps `script-src 'self'` with no `blob:` (§6.3, §6.6, §7).
- **Session-resume bridge** — on a public route, if the Auth0 SDK's JS-readable
  `is.authenticated` hint cookie is present, show a "Resuming your session…"
  screen and kick off the login redirect immediately instead of showing `Landing`
  (§6.8, §12 Q20). A pure `authHint` helper reads the cookie; no React, no token.
- **Session bootstrap** — a gate that waits for the Auth0 SDK to initialise, then
  runs `GET /v1/me`, then renders the frame; terminal handling for
  `403 account-deleted`, retry handling for `503 auth-unavailable` and network
  failure.
- **React-free authed API client** — a framework-agnostic module (`createApiClient`)
  that attaches the bearer token and an `X-Request-Id`, resolves the base URL per
  environment, maps `application/problem+json` to a typed `ApiError`, retries once
  on a `401` after a silent token refresh, and validates 2xx bodies against the
  matching `@sin/core` Zod schema (dev/test hard, prod warn). Consumes `@sin/core`
  DTO types via `z.infer` — **no codegen** (Spec 03.0 P2). Plus a thin React
  binding (`useApi`) and the `me` query used by the bootstrap gate.
- **App frame (minimal)** — routing (`react-router` v7, library mode), a
  `ProtectedRoute` wrapper, a full-screen loading state, an unauthenticated
  landing screen, a `/callback` handler, terminal screens (auth error, account
  deleted, retry, not found), and — inside the protected area — a **placeholder
  authed view** ("You're signed in as …", a "Log out" control). The styled
  `AppShell` with thumb-zone bottom navigation is **Spec 04.1**.
- **Observability seams** — `reportError()` / `track()` no-ops (Spec 13 swaps in
  Sentry / PostHog) and a client-supplied `X-Request-Id` for log correlation.
- **Deployment** — `apps/web` → Render **static site** with SPA fallback
  (`/* → /index.html`), per-environment `VITE_*` build vars, Node 22 build, a
  strict `Content-Security-Policy` + companion security headers, long-cache
  headers on hashed assets.
- **CI wiring** — `@sin/web` typecheck + lint + Vitest/RTL unit tests + production
  `vite build` + a `render.yaml` CSP/header assertion, added to the existing
  pipeline, blocking merge on failure.
- **Cross-doc edits** — DESIGN §3.2 / §5.1 / §7 / §8.2 / §9 and Q10 / Q12 in the
  decisions log; `specs/README.md` rows 04.0 / 04.1 and the cross-cutting
  ownership list.

### Non-goals

- **The design system and any real screen** — `tokens.css`, the CSS reset, the UI
  primitives, the styled `AppShell` + bottom nav, `useSession`, the Profile
  screen (`GET`/`PATCH /v1/me`), and the React error boundary are **Spec 04.1**.
- **Any feature screen** — workout logging + exercise picker (Spec 06), history /
  progress (Spec 08), routines (Spec 10), account export/delete UI (Spec 12).
- **Native mobile** (post-v1). `createApiClient` / `ApiError` / `problem.ts` /
  `requestId.ts` and the Auth0 wrapper are written as plain non-React modules so a
  future React Native app can lift them (DESIGN §3.4 principle 4); promoting them
  into a shared package is deferred (§12 Q13).
- **Offline / PWA / the R1 write-queue** — DESIGN §5.3 / R1, lands in M4. This
  spec only leaves the seam (one API-client module and a TanStack Query cache the
  queue would wrap).
- **Sentry + PostHog** — Spec 13. No-op seams only.
- **E2E / Playwright** — the DESIGN §8.3 happy-path browser smoke is authored with
  the first feature that makes it meaningful (M1, Spec 06). §10 lists the auth
  obligations that smoke must cover.
- **API-side auth, CORS, rate-limit rules** — owned by Spec 01; this spec only
  supplies the deployed web origin for the `WEB_ORIGIN` allowlist.
- **Auth0 tenant / API / Action provisioning** — Spec 01 owns those. This spec
  adds the **SPA application** registration to the same tenant (§8 checklist).

## 2. Acceptance criteria

Behavioural criteria (AC3–AC13) each get ≥1 Vitest/RTL test naming their number
(`describe("AC7 — …")`). AC1–AC2 and AC14–AC17 are build / CI / deploy criteria —
see §10 for the method against each. AC18 is the coverage-of-criteria check.

1. **Builds in the workspace.** `pnpm install && pnpm -r build` produces
   `apps/web/dist/` with a hashed asset manifest and an `index.html` that
   references only hashed, same-origin assets and contains no inline
   script/style/event-handler; `pnpm --filter @sin/web typecheck` and
   `pnpm --filter @sin/web test` pass; `apps/web` resolves `@sin/core` by package
   name with no unresolved-import warning.
2. **Config fails fast.** `import.meta.env` is parsed by a Zod schema at module
   load; a missing/blank `VITE_AUTH0_DOMAIN`, `VITE_AUTH0_CLIENT_ID`,
   `VITE_AUTH0_AUDIENCE`, or `VITE_API_BASE_URL` throws before React mounts and
   `main.tsx` renders a static plain-HTML "misconfigured" page, never a blank
   screen.
3. **Landing when unauthenticated and no prior session.** Visiting `/` with no
   Auth0 session and **no** `is.authenticated` hint cookie renders the landing
   screen — app name, one-line value prop, a single "Log in" control, no
   authenticated chrome — issues **no** request to `/v1/*`, and does **not**
   auto-redirect.
4. **Session-resume bridge.** Visiting a public route (`/`) while the Auth0
   SDK's JS-readable hint cookie (`auth0.{clientId}.is.authenticated` — exact
   name pinned at implementation) **is present** renders a "Resuming your
   session…" screen and immediately calls `loginWithRedirect` (carrying
   `returnTo` for the intended path); `Landing` is not shown and its "Log in"
   control is never rendered. With the cookie **absent**, no redirect fires and
   `Landing` renders (AC3). A `?signin` query flag on `/` **suppresses** the
   auto-resume for that visit (renders `Landing` even with the cookie present) —
   the escape hatch `AuthError` and the `ResumingSession` link route to, so a
   stale cookie cannot loop the user back into `loginWithRedirect`. The
   hint-cookie read is a pure helper (no React).
5. **Login kicks off PKCE.** Activating "Log in" (or the AC4 auto-resume) calls
   `loginWithRedirect` with `authorizationParams.audience === VITE_AUTH0_AUDIENCE`,
   `authorizationParams.redirect_uri` equal to the `/callback` URL, and
   `authorizationParams.scope` including `offline_access` (asserted against a
   mocked `@auth0/auth0-react`).
6. **Callback completes or fails cleanly.** The `/callback` route calls the SDK
   redirect handler; on success it navigates to `appState.returnTo` (default
   `/app`) and drops the `code`/`state` query params; on an Auth0 `error` param it
   renders an auth-error screen with a "Try again" control that returns to
   `/?signin` (the `?signin` flag suppresses the auto-resume for that visit — see
   §6.8 — so a stale hint cookie does not bounce the user straight back into a
   redirect).
7. **Tokens live in memory only.** `Auth0Provider` is configured
   `cacheLocation="memory"`, `useRefreshTokens={true}`,
   `useRefreshTokensFallback={false}` (§12 Q19). After a mocked successful login,
   no access-token- or refresh-token-shaped value is present in `localStorage`,
   `sessionStorage`, or `document.cookie`; a test asserts this and a source scan
   asserts no module reads/writes `localStorage`/`sessionStorage` for token data.
8. **Refresh-token worker is self-hosted.** `Auth0Provider` is passed a
   `workerUrl` pointing at a same-origin path; the production build copies
   `@auth0/auth0-spa-js/dist/auth0-spa-js.worker.production.js` into
   `apps/web/dist/` at that path; the CSP contains **no** `blob:` source and
   **no** `worker-src` relaxation (`script-src` stays `'self'`).
9. **Session bootstrap order.** Once the SDK reports `isAuthenticated` and
   `!isLoading`, the app issues **exactly one** `GET /v1/me` carrying
   `Authorization: Bearer <token>` and a non-empty `X-Request-Id`, and renders the
   protected frame only after that request resolves `200`. `isNewUser: true` in
   the body is treated as success. (Test runs without React StrictMode
   double-mount; the "exactly one" guarantee also relies on TanStack Query
   request de-duplication — the test asserts both the mock call count and that the
   query key is shared.)
10. **Bootstrap failure modes.** `403` + `type` `.../account-deleted` from
    `/v1/me` renders a terminal "account deleted" screen and calls `logout`;
    `503` + `type` `.../auth-unavailable` renders a retry screen and does **not**
    log out; a network error renders the same retry screen. Retry re-issues
    `GET /v1/me`.
11. **Typed errors from problem+json.** A non-2xx `application/problem+json`
    response is thrown by the client as an `ApiError` exposing `status`, `type`
    (slug), `title`, `detail`, `errors[]`, and the sent `requestId`. A non-JSON
    body or a connection failure becomes an `ApiError` with `type: "about:blank"`,
    `status: 0`, and `isNetworkError === true`.
12. **401 → one silent retry.** On a `401` (`unauthenticated` / `invalid-token`)
    and not already retried, the client calls `getToken({ ignoreCache: true })`
    once and retries the request once with the fresh token; a second `401`
    propagates as an `ApiError` and the client invokes `onAuthLost()`. If the
    token refresh itself throws (`missing_refresh_token` on a cold cache, or a
    rotation failure), that is treated as a lost session: `onAuthLost()` is
    invoked and an `ApiError` (`status: 0`, `isNetworkError: false`,
    `type: "about:blank"`) is thrown.
13. **Protected routes.** An unauthenticated visit to a protected path renders
    nothing sensitive and redirects to `/` with the requested path captured as
    `returnTo` (in router state, never from a query param); after a mocked login
    the router lands the user back on that original path.
14. **CSP + headers in `render.yaml`.** The blueprint sets, on `/*`, a
    `Content-Security-Policy` with at least `default-src 'self'`; `connect-src`
    limited to `'self'` + the API origin + the Auth0 domain; `frame-src` the
    Auth0 domain; `script-src 'self'` (no `unsafe-eval`, no `unsafe-inline`, no
    `blob:`); `style-src 'self'`; `base-uri 'none'`; `object-src 'none'`;
    `frame-ancestors 'none'`; `form-action 'self'` — plus
    `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. A CI
    step parses `render.yaml` and asserts every directive.
15. **CSP enforced on the deployed site.** After deploy, a check fetches the live
    site root and asserts the response carries the CSP + `nosniff` +
    `Referrer-Policy` headers with the same directives as `render.yaml`.
16. **CI gates the web app.** The pipeline runs `@sin/web` lint, typecheck,
    Vitest unit tests, and a production `vite build` on every PR and blocks merge
    on any failure.
17. **Deploys as a static site.** Merge to `main` deploys `apps/web` to the
    Render static site with the SPA rewrite (`/*` → `/index.html`) on a Node 22
    build; a deep-link to a protected path (`/app`) served cold returns
    `index.html` (`200 text/html` containing `<div id="root">`) and the client
    then resolves auth + routing.
18. Each behavioural criterion (3–13) has ≥1 committed test tagged with its
    number; 1–2 and 14–17 are verified by CI / review per §10.

## 4. Data model

N/A — the SPA owns no tables and runs no migrations. Client-side state:

- **Auth state** — held by `@auth0/auth0-react` in memory (§7). Not persisted.
- **Server cache** — TanStack Query in memory; the `me` query is the only one
  this spec defines. No persistence in v1 (the R1 `localStorage` mirror is M4 and
  is scoped to in-progress workout data, not to `me` or to tokens).
- **Config** — `import.meta.env` (`VITE_*`), baked into the bundle at build time,
  parsed once into a typed `config` object.

### Loading & gating

```
main.tsx

    <QueryClientProvider>

                                       #         cookie absent          → <Landing/> (no redirect, no /v1 call)
                                       #      on a protected route → <ProtectedRoute> redirects to / with returnTo
                                       # 3. if isAuthenticated → run `me` query
                                       #      pending  → <Spinner/>
                                       #      403 account-deleted → <AccountDeleted/> + logout()
                                       #      503 auth-unavailable / network → <RetryScreen/>

```

### Flow — first login (mobile browser)

```
User          SPA (browser)                 Auth0                       API
 |  tap "Log in"  |                            |                          |
 |--------------->| loginWithRedirect(         |                          |
 |                |   audience, redirect_uri,  |                          |
 |                |   scope: offline_access)   |                          |
 |                |---- 302 to /authorize ---->|                          |
 |                |                            |  hosted login (pw/Google/Apple)
 |<------------------------- user authenticates ---------------------------|
 |                |<-- 302 /callback?code&state |                         |
 |                | handleRedirectCallback():   |                         |
 |                |   code + verifier --------->| /oauth/token            |
 |                |<-- access + refresh token --| (kept in memory only,   |
 |                |                            |  refresh token isolated  |
 |                |                            |  in the self-hosted worker)
 |                | navigate(returnTo ?? /app)  |                         |
 |                | getAccessTokenSilently() -> Bearer                    |
 |                | GET /v1/me  (Bearer, X-Request-Id) ----------------->  |  provision user (Spec 01 §6.2)
 |                |<----------------- 200 { ..., isNewUser: true } ------  |
 |                | render protected frame      |                         |
```

### Flow — returning within a live tab

`getAccessTokenSilently()` returns the cached access token, or the worker uses the
in-memory **refresh token** (rotation) to mint a new one with no redirect. The
`me` query is already warm; the frame renders immediately.

### Flow — cold load / hard reload (in-memory cache is empty)

The SDK has no token and no refresh token → `isAuthenticated` is `false`.
`PublicEntry` checks the Auth0 hint cookie (§6.8):

- **present** (a prior session on this browser) → `<ResumingSession/>` +
  `loginWithRedirect`. If the Auth0 **session cookie** on Auth0's domain is still
  valid the round-trip is silent (no credential re-entry) — a full-page redirect,
  ~1s — and the user lands back on `returnTo`. If it has expired, Auth0 shows its
  login page.
- **present but `?signin` is on the URL** → auto-resume is suppressed for that
  visit; render `<Landing/>`. This is the escape hatch for a stale hint cookie
  (the SDK only clears it on explicit logout, so it can outlive the Auth0 session
  cookie): `AuthError` "Try again" and the `ResumingSession` manual link both
  route here so a failed/cancelled resume cannot loop straight back into
  `loginWithRedirect`.
- **absent** → `<Landing/>`; the user taps "Log in" to start fresh.

The full-page redirect on cold load is the accepted cost of the memory-only token
decision (§7, §12 Q12); the bridge makes it an expected, labelled step rather than
a silent bounce. `useRefreshTokensFallback` is `false` (§12 Q19) so there is no
hidden-iframe attempt — one deterministic path.

### Landing / terminal screens

- `Landing` — name, one line ("Log your lifts. See the numbers move."), "Log in"
  (Auth0 Universal Login covers sign-up too). Shown only when the hint cookie is
  absent (§6.8).
- `ResumingSession` — "Resuming your session…" + a spinner; transient, immediately
  triggers `loginWithRedirect`. Its only control is a "Go to sign in" link to
  `/?signin` — a manual escape if the redirect never completes (stale hint
  cookie, or repeated cancels at Universal Login).
- `AuthError` — "Couldn't sign you in", `error_description` shown verbatim only if
  it is an Auth0-provided string, "Try again" → `/?signin`.
- `AccountDeleted` — "This account has been closed", contact line, auto `logout`.
- `RetryScreen` — "Couldn't reach the server", the failing `requestId`, a "Retry"
  control that re-runs `GET /v1/me`.
- `NotFound` — "Page not found", link to `/app` (or `/` when unauthenticated).
- `AuthedPlaceholder` — "You're signed in as `<email>`", a "Log out" control.
  Exists only to prove the authed frame; Spec 04.1 replaces it.

- `tsconfig.json` **diverges from `tsconfig.base.json`**: `moduleResolution:

The URL fields use a custom `isHttpUrl` refine (via `new URL()`) rather than

### 6.3 Auth0 provider

```tsx
<Auth0Provider
  domain={config.VITE_AUTH0_DOMAIN}
  clientId={config.VITE_AUTH0_CLIENT_ID}
  authorizationParams={{
    audience: config.VITE_AUTH0_AUDIENCE,
    redirect_uri: `${window.location.origin}/callback`,
    scope: "openid profile email offline_access",   // offline_access → refresh token
  }}
  cacheLocation="memory"
  useRefreshTokens={true}
  useRefreshTokensFallback={false}                   // §12 Q19 — deterministic cold-load redirect
  workerUrl="/auth0-spa-js.worker.production.js"     // self-hosted; see below
  onRedirectCallback={(appState) => navigate(appState?.returnTo ?? "/app")}
>
```

- **`cacheLocation="memory"`** — tokens (access **and** refresh) live only in a JS
  closure / the worker; nothing in web storage or a readable cookie (§7, §12).
  The SDK still sets a non-token `auth0.is.authenticated` hint cookie — acceptable,
  it carries no credential.
- **Self-hosted refresh-token worker.** With `cacheLocation="memory"` +
  `useRefreshTokens`, `@auth0/auth0-spa-js` isolates the refresh token in a Web
  Worker. **By default it builds that worker from a `blob:` URL**, which a strict
  `script-src 'self'` / no-`blob:` CSP blocks — the refresh flow would break in
  production while passing in jsdom. The SDK also ships the worker as a standalone
  file (`@auth0/auth0-spa-js/dist/auth0-spa-js.worker.production.js`). We copy
  that file into `apps/web/dist/` via `vite-plugin-static-copy` and pass
  `workerUrl` (a same-origin path) to the provider (`@auth0/auth0-react` forwards
  unknown options to the underlying `Auth0Client`; confirm the exact prop name at
  implementation). Result: the worker loads under `script-src 'self'`, no CSP
  relaxation (§6.6, §7, AC8, AC14).
- **`useRefreshTokensFallback={false}`** (§12 Q19). With it `false` a cold load
  goes straight to the redirect — one deterministic, testable path. The SDK
  default (`true`) would first attempt a hidden `prompt=none` iframe, which cannot
  succeed on the majority mobile browsers (Safari / Firefox block third-party
  cookies) and so only adds a failed-iframe timeout before the redirect those
  users get anyway. `BootstrapGate` treats a `missing_refresh_token` /
  `login_required` outcome as "not authenticated". The **session-resume bridge**
  (§6.8) is what keeps that cold-load redirect from feeling like a random bounce.

### 6.4 API client (`api/client.ts`)

`createApiClient({ baseUrl, getToken, onAuthLost })`:

1. Build the URL from `baseUrl` + path; set `method`, JSON-serialise `body`.
2. Headers: `Authorization: Bearer ${await getToken()}`, `Content-Type:
   application/json` (on write), `Accept: application/json`, `X-Request-Id:
   crypto.randomUUID()` (secure context — our origins qualify; §9).
3. `fetch`. On a thrown / `TypeError` (DNS, offline, CORS) → `ApiError` with
   `status: 0`, `type: "about:blank"`, `isNetworkError: true`.
4. `401` **and** not already retried → `await getToken({ ignoreCache: true })`
   (maps to `getAccessTokenSilently({ cacheMode: "off" })`), retry the request
   once. A second `401` → call `onAuthLost()` and throw the `ApiError`. **If
   `getToken({ ignoreCache: true })` itself throws** (`missing_refresh_token` on a
   cold cache, or a rotation-reuse failure) → call `onAuthLost()` and throw an
   `ApiError` (`status: 0`, `type: "about:blank"`, `isNetworkError: false`).
5. Non-2xx → parse the body:
   - `application/problem+json` → `ApiError` from `{ type, title, status, detail,
     errors }` (Spec 01 §5). `errors[]` passes through as-is (already value-free
     per Spec 03.0 §6.2). `type` is stored as its slug (last path segment).
   - anything else → `ApiError` with a generic title, keep `status`.
6. `2xx` → parse JSON, then `schema.parse(body)` where the caller passed a
   `@sin/core` schema. **Dev/test** (`VITE_APP_ENV` ≠ `production`): a parse
   failure throws (surfaces contract drift in CI). **Production:** parse failure
   is logged via `reportError()` and the raw body is returned (a benign additive
   server field must not break a user mid-workout).

The module imports **no React** — it takes `getToken` / `onAuthLost` as
callbacks. `useApi()` binds it to `useAuth0().getAccessTokenSilently` and a
`logout`-based `onAuthLost`. This is the seam a React Native app reuses (DESIGN
§3.4).

### 6.5 Bootstrap gate

`useMe()` is `useQuery({ queryKey: ["me"], queryFn: () => api.get("/v1/me",
MeSchema), enabled: isAuthenticated, retry: (n, e) => !(e instanceof ApiError &&
[401, 403].includes(e.status)) && n < 2 })`. `BootstrapGate` renders on the
result: `pending → <Spinner/>`, `error & 403 account-deleted → <AccountDeleted/>`
(+ `logout`), `error & (503 | network) → <RetryScreen onRetry={refetch}/>`,
`success → children`. `isNewUser` is ignored here (a hint for a future onboarding
screen, not this spec). The AC9 test disables StrictMode double-mount and asserts
the mock was called once *and* that the same `["me"]` query key is reused (TanStack
Query de-dupes concurrent fetches).

### 6.6 CSP-compatible build

Three things could force a CSP relaxation; all are removed at build time so the
policy stays `default-src 'self'` with `script-src 'self'` / `style-src 'self'`:

1. **Module-preload polyfill.** Vite can emit one inline script for it; set
   `build.modulePreload.polyfill = false` (current mobile Safari/Chrome support
   `modulepreload` natively) → no inline script, no hash needed.
2. **Auth0 refresh-token worker.** Default is a `blob:` worker (§6.3); we
   self-host the shipped worker file and point `workerUrl` at it → loads under
   `script-src 'self'`, no `blob:` / `worker-src`.
3. **Injected styles.** CSS from CSS Modules (Spec 04.1) is emitted as external
   hashed `.css` (`style-src 'self'`). If a dependency is later found to inject a
   `<style>` tag at runtime, that is a review gate, not a silent `unsafe-inline`.

`index.html` contains no inline event handlers or scripts. A build-output check
(AC1) asserts this over `dist/`.

### 6.7 Routing & protected routes

`react-router` library mode (`createBrowserRouter`). `ProtectedRoute` reads
`useAuth0().isAuthenticated`; if false it renders `<Navigate to="/"
state={{ returnTo: location.pathname + location.search }} replace />`. `Landing`'s
"Log in" passes `appState: { returnTo }` into `loginWithRedirect`, so
`onRedirectCallback` lands the user back where they started (AC13). The protected
layout route renders `<Spinner/>` while `BootstrapGate` is pending and an
`<Outlet/>` on success; Spec 04.1 swaps the layout element for `<AppShell>`.

### 6.8 Session-resume bridge (public routes)

The memory-only token choice (§7, §12 Q12) means every cold load / hard reload
starts with `isAuthenticated === false`. Without a bridge the user would see
`Landing` and have to tap "Log in" to resume a session the browser could restore
silently. `PublicEntry` — the element behind `/` (and any future public route) —
handles this:

- On mount, `!isLoading && !isAuthenticated`, it calls
  `authHint.hasAuth0Session()` — a **pure helper** (`src/auth/authHint.ts`, no
  React) that reads `document.cookie` for the Auth0 SDK's JS-readable hint
  (`auth0.{clientId}.is.authenticated=true`; the SDK also writes a legacy
  `auth0.is.authenticated` — the helper accepts either, exact key pinned at
  implementation against the installed SDK).
- **Cookie present, no `?signin`** → render `<ResumingSession/>` ("Resuming your
  session…", a spinner) and immediately call
  `loginWithRedirect({ appState: { returnTo } })` with `returnTo` = the intended
  post-login path (`/app`, or a captured deep link). `Landing` and its "Log in"
  control never render.
- **Cookie present, `?signin` on the URL** → auto-resume is suppressed for that
  visit; render `<Landing/>`. The SDK only clears the hint cookie on explicit
  logout, so it can outlive the Auth0 session cookie; without this flag a
  stale-cookie `PublicEntry` mount would call `loginWithRedirect` again the
  moment the user returns from a failed or cancelled resume, and repeated
  Back / cancel would loop. So the `/callback` error path (AC6) sends "Try again"
  to `/?signin`, and `<ResumingSession/>` carries a "Go to sign in" link to the
  same, both landing on `<Landing/>` with its explicit "Log in". (One residual
  gap — a raw browser Back from Universal Login hits bare `/` and auto-resumes
  once more; bounded, not a loop — is tracked as BL-2.)
- **Cookie absent** → render `<Landing/>` unchanged; no redirect, no `/v1` call
  (AC3).
- `authHint` never reads a token or anything credential-bearing — only the
  boolean hint cookie the SDK maintains for exactly this purpose.

This is the near-term mitigation for the tab-eviction limitation in §12 Q21: the
redirect still happens, but it is expected and labelled rather than a silent
bounce back to a login screen.

### 6.9 Logout

`logout({ logoutParams: { returnTo: window.location.origin } })` clears the
in-memory cache and redirects to Auth0's `/v2/logout` then back to `/`. The origin
must be in the Auth0 app's Allowed Logout URLs (§8). Auth0 also clears its
`is.authenticated` hint cookie on logout, so the next visit to `/` shows
`Landing`, not the resume bridge.

## 7. Security & privacy

### Token storage — the load-bearing decision (Q12)

**Access and refresh tokens are held in memory only** (`cacheLocation="memory"`),
with the refresh token further isolated in the self-hosted worker. Rationale, from
first principles:

- An SPA has no server session, so *something in the browser* holds the
  credential. The choice is memory (a JS closure / worker, gone on reload) vs. web
  storage (`localStorage` / `sessionStorage`, survives reload, **readable by any
  script on the origin**).
- Training logs + body weight are sensitive personal data (DESIGN §8.2). A
  **refresh token in `localStorage` is the highest-value target for an XSS bug**:
  one injected script exfiltrates it and mints access tokens indefinitely, even
  after the tab closes. In memory, an XSS still does damage while it runs, but
  there is no persisted long-lived credential to steal, and closing the tab ends
  it.
- We cannot fully rule out XSS in a React app with third-party dependencies, so we
  do not want the worst case to be "permanent account compromise".

**Cost:** on a cold load or hard reload the in-memory cache is empty, so the user
re-establishes the session with a full-page redirect to Auth0 (silent if the
Auth0 session cookie is valid — no credential re-entry, ~1s). How that degrades is
settled (§12 Q19–Q21): `useRefreshTokensFallback: false` (one deterministic
redirect path), a **session-resume bridge** (§6.8) so the redirect is a labelled
"Resuming your session…" step rather than a `Landing` bounce, and an accepted
limitation that an OS-evicted background tab still costs a redirect mid-workout
until local session persistence lands with R1 at M4. Revisit the storage choice
itself only if that cost proves frequent in real use, and then only paired with a
tightened CSP.

### CSP & headers (AC14/AC15, DESIGN §8.2)

Served as **response headers** from the Render static site (stronger than a
`<meta>` tag — covers non-HTML responses and `frame-ancestors`):

```
Content-Security-Policy:
  default-src 'self';
  connect-src 'self' https://<api-origin> https://<auth0-domain>;
  frame-src https://<auth0-domain>;
  script-src 'self';
  style-src 'self';
  img-src 'self' data:;
  font-src 'self';
  worker-src 'self';
  base-uri 'none'; object-src 'none'; frame-ancestors 'none';
  form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Strict-Transport-Security: max-age=31536000; includeSubDomains   # Render also sets this
```

- **No `blob:`, no `unsafe-inline`, no `unsafe-eval` anywhere.** `worker-src
  'self'` is present as an explicit allow for the self-hosted Auth0 worker (it is
  same-origin, so this is not a relaxation — browsers that lack `worker-src` fall
  back to `script-src 'self'`, which also covers it).
- `connect-src` currently lists only the API + Auth0 origins. **Future
  `connect-src` entries (Sentry ingest, PostHog) land with Spec 13**, not here.
- The API origin in `connect-src` and the web origin in the API's exact-match
  `WEB_ORIGIN` CORS allowlist (Spec 01 §5.5) are two ends of the same rule and
  must be updated together whenever a deployed hostname changes (§8 checklist).

CSP is the *primary* XSS mitigation; the in-memory-token choice is defence in
depth behind it, not a substitute.

### Other

- **No secrets in the bundle.** PKCE public clients have no client secret. The
  Auth0 `domain`, SPA `clientId`, and `audience` are public by design (they appear
  in the `/authorize` redirect URL). `VITE_*` vars are build-time constants,
  documented as non-secret in `.env.example`.
- **Bearer, not cookies.** Tokens travel in the `Authorization` header; no
  credentialed CORS (matches Spec 01 §5.5, `credentials: false`).
- **Redirect allowlisting.** `returnTo` is only ever an in-app pathname captured
  from `location` (router state), never a query param or external input — it
  cannot drive an open redirect.
- **Error hygiene.** The client surfaces `ApiError.detail` / `errors[]` as the API
  sent them (already value-free per Spec 01 / 03.0); the app never renders a raw
  stack trace or the access token. `reportError()` is a no-op until Spec 13 and
  must never be passed a token.
- **PII.** `email` is rendered in `AuthedPlaceholder` (the user's own data) but
  must never be put into `X-Request-Id`, analytics event names, or `reportError()`
  metadata (DESIGN §8.1).
- **Auth0 app config.** Refresh Token Rotation on with a bounded absolute
  lifetime; Allowed Callback / Logout / Web-Origin URLs are the exact env origins
  only (no wildcards).

## 12. Decisions & open questions

**No open questions block this spec.** Q10, Q12–Q15, Q17–Q21 are resolved below
(Q14 and Q18 were closed during review); Q16 is deferred to Spec 04.1 and Q11 is
decided there.

### Resolved

- ✅ **Q10 — Router + data layer: React Router (library mode) + TanStack Query.**
  DESIGN §3.2 hedged "React Router (or TanStack Router)"; resolved to **React
  Router v7 in library mode** (`createBrowserRouter`, no framework/SSR layer) — it
  is the most widely used option (community, docs, job-market signal), and library
  mode is a small API surface for a developer learning React. TanStack Router's
  codegen'd typed routes add tooling for little v1 payoff. **TanStack Query** for
  server-state caching is kept from DESIGN §3.2; this spec configures the client
  and defines only the `me` query.

- ✅ **Q12 — Browser token storage: in memory only.** `@auth0/auth0-spa-js`
  `cacheLocation="memory"` + `useRefreshTokens` (rotation). A persisted refresh
  token (`localStorage`) is the highest-value XSS target on a sensitive-PII app
  (DESIGN §8.2); memory-only means an XSS has no long-lived credential to
  exfiltrate and closing the tab ends the exposure. CSP (§7, AC14) is the primary
  XSS control; this is defence in depth. The cold-load cost is shaped by Q19
  (deterministic redirect), Q20 (resume bridge), and the accepted limitation Q21.
  Revisit the storage choice itself only if that cost proves frequent in real gym
  use, and then only paired with a tightened CSP.

- ✅ **Q13 — API client + auth wrapper stay in `apps/web` for now, written
  React-free.** `createApiClient` / `ApiError` / `problem.ts` / `requestId.ts` and
  the Auth0 wrapper take callbacks, import no React, and touch no DOM beyond
  `fetch` / `crypto.randomUUID` — so a future `apps/mobile` lifts them or they are
  promoted to a `packages/api-client`. Not promoting now: no second consumer
  exists (YAGNI, DESIGN §3.4 principle 6), and `@sin/core` is deliberately pure
  data/math (Spec 02 §1 parks the client here).

- ✅ **Q14 — Render static-site blueprint shape confirmed** against the current
  Render Blueprint YAML reference (`runtime: static`, `staticPublishPath`,
  `routes` with `type: rewrite`, `headers` with `path`/`name`/`value`). Exact keys
  re-verified at implementation; not a blocking unknown.

- ✅ **Q15 — Response validation is dev-hard / prod-warn.** The client
  `schema.parse()`s 2xx bodies against `@sin/core` schemas; a mismatch **throws**
  in `local`/`staging`+test (catches contract drift in CI) but **logs and passes
  through** in `production`. Gated on `VITE_APP_ENV`.

- ✅ **Q17 — CSP delivered as Render response headers, and the build made
  CSP-clean.** Three would-be relaxations removed at build time (§6.6):
  `build.modulePreload.polyfill=false` (no inline script), **the Auth0
  refresh-token worker is self-hosted** (`workerUrl` → same-origin file, not the
  default `blob:` worker), and CSS Modules emit external CSS. Result: `script-src
  'self'` / `style-src 'self'` / `worker-src 'self'`, no `blob:` / `unsafe-*`.
  Headers (not a `<meta>` tag) so `frame-ancestors` and non-HTML responses are
  covered.

- ✅ **Q18 — React 19 + peer deps: confirmed compatible.** As of 2026-09,
  `@auth0/auth0-react` 2.24.x declares a React 19 peer range, `react-router` v7
  peers `react >= 18`, and `@tanstack/react-query` v5 supports 18/19. Pin exact
  versions at implementation. No React-18 fallback needed.

- ✅ **Q19 — `useRefreshTokensFallback: false`.** On a cold load the SDK goes
  straight to the full-page redirect — one deterministic, testable path — rather
  than first attempting a hidden `prompt=none` iframe. The product is mobile-first
  and iOS-Safari-heavy; on Safari and Firefox the iframe cannot succeed
  (third-party-cookie block), so `true` would only add a failed-iframe timeout
  before the redirect those users get anyway — all cost, no benefit for the
  majority browser. `false` also removes the "hanging iframe" failure mode from
  the state machine. This is a one-line additive flip: revisit if analytics later
  show a meaningful desktop-Chrome share for whom cold-load redirects are measured
  friction.

- ✅ **Q20 — Session-resume bridge, in 04.0.** On a public route, if the Auth0
  SDK's JS-readable hint cookie (`auth0.{clientId}.is.authenticated` — exact name
  pinned at implementation) is present, render `<ResumingSession/>` ("Resuming
  your session…") and call `loginWithRedirect` immediately instead of showing
  `Landing`; when the cookie is absent, `Landing` renders as before (§6.8, AC3 /
  AC4). A pure `authHint` helper reads the cookie — no React, no token. This turns
  the Q19 cold-load redirect from a silent bounce into an expected, labelled step.

- ✅ **Q21 — Accepted known limitation: tab-eviction still costs a redirect.**
  Memory-only tokens mean an iOS-Safari background tab that the OS evicts (e.g.
  during a long rest period) comes back with an empty cache and must cold-load →
  redirect, mid-workout. In-progress workout data is server-persisted (DESIGN
  §5.3) so nothing is lost, and Q20's bridge makes the redirect expected rather
  than jarring, but the interruption is real. The full fix is local session
  persistence, which arrives with the R1 offline mitigation at **M4** (DESIGN
  §5.3). Accepted for M0–M3; not an open question.

### Deferred (owned elsewhere)

- **Q16 — the one vertical slice (Profile).** Now **Spec 04.1**.
- **Promotion of the API client to `packages/api-client`** — when `apps/mobile`
  starts (Q13).

# packages/core (`@sin/core`)

Routine-from-text conventions (Spec 10.4, core reader and web import), moved here from the root `CLAUDE.md`. The web screens it mentions live in `apps/web/`.

## Conventions & gotchas

- **Routine from text** (Spec 10.4): the reader is pure `@sin/core` (`readWorkoutText`, `buildImportPlan`; furniture lists are constants; notices are codes, messages static); the import session is in memory only (no storage key, no URL state) and `USER_DATA_KEY_PREFIXES` is unchanged; an imported item carries a placeholder exercise id that exists only in the draft and the session — `saveImport` creates the still-referenced pending exercises online-only and substitutes ids in the request body only; a retry reuses `created`; `ExerciseFields` is the one set of create-exercise inputs (`CreateExerciseForm` and the import's New card); `ExercisePicker allowCreate={false}` for any caller that must not create; the screens harness types the fixture `packages/core/test/fixtures/hiraya-2026-10-19.txt`. `RoutineEditor` takes an optional `initial` (`draft`, `notices`, `prepareBody`, awaited by Save before the routine write) and `PendingExercisesContext` lets `useExerciseLookup` answer for placeholders (`isNew`), so no other consumer changes. The import session also mirrors the import's own history entries in memory (`useImportHistory`, a cursor over location keys; never router state): Back to text goes Back when the paste screen is behind it, and Save leaves through `EditorStart.leaveTo`, which goes back to the first import entry and replaces it with the preview, so one Back returns to where the import began. Round 2 (AC42–AC54): a clock line may carry one icon (`11:08 →`), symbol-only icon lines are furniture anywhere but a short non-Latin word only beside the tab bar or a clock at a screenshot's top (a mid-text `4:00` opens no window, #168), the overlap compares `ocrKey`s (case kept except same-shape letters; headers compare without case via `headerKey`), and when a paste has header badges (`NO SCORE`, `REPS`…) the line above a badge (`CleanResult.tagged`) and the strict headers (`Workout: "X"`, the `HEADING_WORDS`) start sections, never a guessed generic title; the variant-label words are `VARIANT_WORDS` (never any line ending `:` — "For Time:" precedes real exercises; never `rx` — an `Rx` line is a note that keeps the run open). A name with no letter or digit keys as `written:<name>` (#169), never `""`. Round 3 (AC55–AC66): a clock may carry a glued digit, one letter or a leading icon (`3:524`, `3:52 A`, `€ 3:53`); the cellular status bar (`isStatusBarLine`: signal-bar tokens, a `NETWORK_NAMES` entry, a short tail), the trophy before and the score after `RESULTS (n)`, and slash-joined badges (`isBadgeLine`, `ROUNDS/REPS`) are furniture; `ocrKey` ignores apostrophes; a ` @ load` is the item's note (`splitLoad`); `L-H Sets` opens L sets; inside a non-Warmup section an un-bulleted counted line (reps, calories or a leading distance, never a time — `20 Minute Cap` stays a note) is a rowless exercise and consecutive ones are one `list` run, so one superset (owner ruling 2026-10-26). All three fixtures (`hiraya-2026-10-19.txt`, `-24.txt`, `-26.txt`) must keep reading as their example tests say. Round 4 (minors, owner rulings 2026-10-28): `20/15 Cal Row` is a calorie form (`LEADING_CAL` takes an `N/N` number); `ReadName.calories` needs **every** item with the key to be a calorie form (mixed `20 Row` / `20 Cal Row` gets no hint); a standalone `Max Cal <movement>` line is an AC62 exercise, other `Max …` lines stay notes; a calorie line under a scheme takes its row count with null reps; a trailing `for time` (and a comma before it) on any movement line goes to the note — on `A + B` the line's goes to every part and a part's own to that part, a line that is structure without it (`Rounds for time`) is the run's note, and a cue sentence ending in it stays a note (minors 215, 216); a scheme or lead-in ending in `for time` (`21-15-9 for time`, `3 Rounds For Time:`) opens its run and stays in the note (`N Sets, for time` is still AC48's strict lead-in) (owner ruling 2026-10-31, minor 283); a status bar with no bars before the network name may carry only a 1–2 character tail (`LTE O` dropped, `LTE Row` kept), and only a tab bar (another label within three lines) is chrome, never a lone `Home`. Bullets and counted lines share one `rowlessItemOf`; the import plan relies on the reader's order (section-ordered, runs consecutive; pinned in the totality test) and always sorts it stably, so an ordered read comes back unchanged (minors 220, 282); a line that is only `for time` under a scheme or lead-in run is the run's note, the colon form only before the run's first movement (AC67, minor 280); a scheme that replaces a lead-in run with no movement yet keeps the lead-in line in the note, in line order, and the sets are the scheme's, so a lead-in count never repeats it (AC68, owner ruling 2026-11-01, minor 284). `prepareCatalog(rows)` is the matcher's index (`matchExerciseName` takes rows or a prepared catalog); build it from the rows shown now.
